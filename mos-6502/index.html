The 6502,
cycle by cycle

A processor small enough to hold in your head: three registers, 56 instructions, and a rule so strict it explains almost everything else about the chip — on every clock cycle it reads one byte or writes one byte. Never none. Never two.

Everything below is produced by a 6502 running in this page. The timing diagrams are its actual bus traces; the quirks are demonstrated by executing them. It passes Klaus Dormann's functional test suite — 30,646,177 instructions — so when it tells you what the chip does, it is not reciting a table.

01 · Origins

The design decision was
a price.

In 1975 a microprocessor cost about $179 and a small team at Motorola had been told to stop arguing about it. They left, went to a calculator-chip company in Pennsylvania, and worked backwards from $25 — which meant a small die, which meant almost no registers, which is why 6502 assembly language looks the way it does. Everything peculiar about this chip is downstream of that number.

      02 · The model

      Three registers,
      and one page of memory that pretends to be more.

      A modern processor has dozens of general registers. The 6502 has one accumulator and two indexes, and the reason is the die budget. What replaced the missing registers is page zero — the first 256 bytes of memory, addressable in a single byte, one cycle faster than anywhere else, and the only place a pointer is allowed to live. On a 6502 machine, page zero is the register file.

      • Notice how much of the 64K map the chip itself has an opinion about: six bytes.

      The programmer's model

      The status register

      Eight bits. Six are flags, one is always 1, and one is a message written only on the way to the stack.

      All 64 kilobytes

      The 6502 has opinions about exactly two regions and six individual bytes. Everything else is whatever the machine's designer decided to wire there — and the processor cannot tell the difference between RAM, ROM and a hardware register.

      03 · Cycles

      One bus access
      per clock cycle. Always.

      This is the rule the whole chip is built around. There is no cycle in which the 6502 is thinking quietly to itself, and no cycle in which it does two things. So an instruction's cycle count is not a lookup in a table — it is the number of bytes it has to move, and you can derive it from first principles.       Why an instruction costs what it costs

      Count the bytes it must move and you have the cycle count, almost always. One for the opcode. One for each operand byte. One for each read or write of data. Then add the cycles the chip spends being wrong:

      • The indexed guess. The 6502 adds the index to the low byte and reads there straight away, before the carry into the high byte is known. If there was a carry, that read was 256 bytes off and has to be done again. Hence "+1 if the index crosses a page".
      • The read-modify-write parking space. There is nowhere to hold a value while the ALU changes it, so the chip writes the old byte back to the bus and then writes the new one. Three accesses to one address, every time.
      • The branch that has to look twice. A taken branch costs one more cycle to add the displacement, and a second if the result left the page — the same missing carry, in the program counter this time.

      What 1 MHz bought you

      One cycle is one microsecond. The average instruction is around three of them, so a 6502 ran roughly 300,000 instructions a second — and every one of those instructions moved at most one byte.

      05 · The ALU

      Two seams
      on the same circle.

      The carry flag and the overflow flag confuse people because they are usually explained separately. They are the same idea twice. A byte is a circle of 256 positions, and an addition is a walk around it — but how far you walk depends on how you read the operand. Read $90 as unsigned and it is 144 steps clockwise; read it as signed and it is 112 steps the other way. You land on the same square either way, because it is the same byte.

      Carry is set when the unsigned walk crosses the seam between $FF and $00. Overflow is set when the signed walk crosses the seam between $7F and $80. Same circle, same destination, two routes, two seams — and each flag is simply a report on one of the routes.

      Try

      • $50 + $50. The operand's top bit is clear, so there is only one walk. It passes the signed seam and not the unsigned one: V set, C clear.
      • $D0 + $90. Now the routes part company — 144 steps one way, 112 the other — and each crosses its own seam. Both flags come up.
      • $50 + $90, where the two walks cross the same seam and yet neither flag is set.
      • Turn on decimal mode and watch three of the four flags start lying.

      The byte as a circle

      Run the adder

      The formula, and why it is that formula

      Every 6502 reference prints the overflow test as a piece of bit arithmetic:

      V = (~(A ^ M) & (A ^ result)) & $80

      Read it as two questions. ~(A ^ M) & $80 asks: did the two inputs have the same sign? If they did not, no signed addition can overflow — adding a positive to a negative always lands between them, which on the circle is the walk that can never reach the far seam. (A ^ result) & $80 asks: does the answer disagree in sign with what we put in? Both true at once, and the only explanation is that the signed walk went past $7F/$80.

      This is not a formula somebody chose. It is roughly four gates, and you can see them in the die photographs.

      Decimal mode, and what it costs you

      SED changes exactly two instructions. ADC and SBC start treating each byte as two decimal digits, so $58 + $46 gives $04 with the carry set — 58 + 46 = 104. Nothing else on the chip notices.

      The bill arrives in the flags. On the NMOS part, the decimal correction happens after N, V and Z have already been set from the binary arithmetic underneath, so only the carry can be trusted after a decimal add. Turn on decimal mode above and add $99 + $01: the answer is $00 with carry, correctly, and the Z flag says the result was not zero.

      The CMOS 65C02 fixed this and charged a cycle for it. Nintendo removed the whole circuit from the NES's processor, which is why no NES program ever executes SED.

      06 · The matrix

      256 opcodes,
      and only 151 of them were meant.

      An opcode is a byte, so there are 256 of them, and MOS Technology documented 151. The other 105 are not errors and not a secret feature — they are what happens when a decode matrix built from sparse transistors meets a bit pattern nobody planned for. Several control lines match at once and two instructions execute simultaneously, in the cycles of one.

      07 · The machine

      A whole computer,
      in about a thousand lines.

      A 6502, 64 kilobytes of memory, a 32 × 32 screen at $0200, a random byte at $FE and a keyboard byte at $FF. That is the entire machine, and it is enough — it is roughly what an Apple I was. Write something, assemble it, and step it one instruction at a time while you watch the registers move.

      Try

      • Load Multiply and single-step it. The 6502 has no multiply instruction; this is how you get one.
      • Load Sort and press Run. Each pass leaves one more bar in place.
      • Break something on purpose — the assembler will tell you what it thinks you meant.

        08 · Interrupts
        
        
        Six bytes
        the chip knows about before it has run anything.
        
        
        At power-on the 6502 knows three addresses and nothing else, and it reads them from the last six bytes of memory. Everything a 6502 machine does — booting, servicing a keyboard, drawing a raster split — starts by putting an address in one of those six bytes. The sequence that follows is identical for all three, down to the cycle.

        09 · Quirks
        
        
        Nine things it does
        that nobody designed.
        
        
        Every one of these is a consequence of a decision that made sense on its own: a carry that was not worth the transistors, a value with nowhere to park, a byte count chosen to save a cycle. None of them is a mystery once you know what the chip was trying to avoid spending.             Colophon
            
        
            No frameworks, no build step, no network. Five files: a 6502 core, a two-pass assembler, the text, a bench that runs the examples, and the page. The core and the assembler are covered by 71 tests, including a round-trip between the assembler and the disassembler over all 256 opcodes, and a check that every instruction's bus trace is exactly as long as its documented cycle count.
