# 2026.06.22 — JRN — Quarto used-piece refresh

Applied a revised Quarto build from `~/Downloads/Quarto.zip` (+ the matching
single-file `Quarto.html`), a follow-on to the [[2026.06.21 lightened-colours
refresh]] and the [[2026.06.20 import]].

## What's in the download
A bundler export: a self-contained `Quarto.html` (sideload build) plus the source
tree — `play.html` (the production shell, *the file you ship*), the design-canvas
`index.html` + its tooling (`design-canvas.jsx`, `ios-frame.jsx`, `tweaks-panel.jsx`,
`quarto-app.jsx` — explicitly *not for shipping* per the README), the six core
`.jsx`, `manifest.json`, `sw.js`, icons, README, screenshots. Our live `quarto/`
slug is the **ship set only**, with `play.html` promoted to `index.html`.

## What actually changed (diff -w against the live slug)
The only genuine upstream changes are **three jsx files**, one coherent feature —
"played pieces read as spent":
- `quarto-iso.jsx`, `quarto-piece.jsx`: new `grey` prop → `grayscale(0.85)
  brightness(0.85)` + lower opacity for desaturating a piece.
- `quarto-board.jsx`: used board cells go from a diagonal-hatch overlay to a darker
  inset well (`rgba(0,0,0,0.28)` + inset shadow) holding a **greyed** piece with a
  red ✗ drawn as two SVG lines stroked in `theme.danger`; pool shows played pieces
  greyed. (`theme.danger` already exists in all three themes — verified.)

Everything else is **content-identical** to the live slug (only CRLF-vs-LF differs):
`play.html`==our `index.html`, `quarto-themes.jsx` (already carries the v2 lightened
`pieceDark`), `quarto-engine.jsx`, `quarto-screens.jsx`, icons. Left them untouched.

## sw.js / manifest.json — kept ours, did NOT wholesale-copy
Same trap as last time: the export's `sw.js` references `./play.html` and **resets**
`VERSION` to `quarto-v1`; its `manifest.json` sets `start_url: ./play.html`. Both are
written for the tool's own layout, not our `index.html` deployment. So I kept our
rewired copies and only **bumped `sw.js` VERSION `quarto-v2` → `quarto-v3`** — the
`.jsx` are cached cache-first, so without the bump a returning/installed visitor
keeps the old board renderer forever. `manifest.json` needs no change (its sole diff
was the `play.html` start_url we reject).

## Line endings
Live slug is CRLF (whole repo is); the download is LF. Converted the three jsx to
CRLF on install so `git diff` shows only the real changed lines, not every line.

## Catalog entry
Left `data.js` unchanged — same document, same tagline/icon/date. A render tweak to
used pieces doesn't warrant a date bump / resurfacing.

## Verified
Served the worktree over HTTP and headless-rendered it: `/quarto/` boots to
onboarding with React mounted on the new jsx (dark pieces still the warm brown).
Served the full export's design-canvas (seeds mid-game boards) and confirmed the
new treatment renders — played pieces in the tray show the red ✗ and desaturate,
proving `theme.danger` resolves and the `grey` prop threads iso←piece←board.

## Re-import note
Unchanged from prior: a future re-import must re-apply `play.html`→`index.html`
promotion, **keep** our `manifest.json`/`sw.js` (don't take the export's
`play.html`/`v1` versions), bump `sw.js` VERSION when an asset behind the SW
changes, and convert LF→CRLF. Cherry-pick the jsx; never wholesale-copy the shell
config.
