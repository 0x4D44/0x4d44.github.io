## Findings (both confirmed by running the shipped engine)
- KILN-00031 (Low): `updateProgression` adjusts difficulty on a SINGLE feedback log —
  `.slice(-3).every()` / `.slice(-2).every()` are vacuously true on short history, so
  one too_easy bumps level, one too_hard drops it. Plus `recentFeedback`/`recentStatuses`
  are filtered independently → misalign on a status-only log. The existing test primes
  2 prior entries so it never hits the short-history case.
- KILN-00032 (Low): `longestStreak` uses `delta === 86400000 ms` to detect consecutive
  days — breaks across a London DST change (23h/25h), splitting a streak. 3 consecutive
  maintained days across spring-forward counted as 2. `currentStreak` is DST-safe
  (setDate); only longestStreak is brittle. Inconsistent.
