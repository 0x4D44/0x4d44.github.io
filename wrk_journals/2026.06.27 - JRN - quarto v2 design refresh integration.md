# 2026.06.27 - JRN - Quarto v2 design refresh integration

Integrated a new Quarto design package (`~/Downloads/quarto.zip`) into the
deployed `quarto/` document. Shipped as commit `9bac759`, ff-pushed to
`origin/main`.

## What the package contained

21 files: the production shell `play.html`, the offline single-file
`Quarto.html`, the design-canvas `index.html` (+ `design-canvas.jsx`,
`tweaks-panel.jsx`, `ios-frame.jsx`, `quarto-app.jsx`), the six game `.jsx`,
`manifest.json`, `sw.js`, icons, `README.md`, screenshots. The README is
explicit: `play.html` is "the file you ship"; the package `index.html` is the
design canvas, "for exploration, not shipping".

## Approach — file-by-file merge, not a wholesale copy

This matched the prior-refresh lesson already in `lessons_learnt.md`. Took from
the package only what advances the deployed shell:

- `index.html` <- package `play.html` (verified the two differ *only* by the
  three forward deltas: atelier default theme, light/dark toggle wiring,
  `qWinBob` keyframe — no deployment-specific internals).
- `quarto-themes.jsx` — brighter salon/atelier/modern accents; new `tileSeat`
  and iso-plinth `board` wood per theme.
- `quarto-screens.jsx` — light/dark toggle button on the home screen.
- `quarto-iso.jsx` — glowing win-tile diamonds, layered win beam, win-piece
  bob/glow; consumes the new `board`/`tileSeat` props.
- `sw.js` — bumped cache `VERSION` quarto-v4 -> quarto-v5 (cache-bust).

Deliberately kept the repo's version of:

- `quarto-board.jsx` — **the package reverts the `{'→'}` JSX-escape fix
  (commit ec2a23f) back to a bare literal `→`.** Its only delta vs the repo
  was that regression, so kept ours. This is exactly the drift the escape lesson
  warned about.
- `manifest.json` — package sets `start_url: ./play.html`; kept `./` for the
  Pages subpath deploy.
- All design-only files — not shipped.

`quarto-engine.jsx`, `quarto-piece.jsx`, and the icons were byte-identical.
