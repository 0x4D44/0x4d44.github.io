# 2026.07.11 — JRN — "The Electric Wake" (cruise-propulsion) mobile fix

## Task
Arthur: review "The Electric Wake" and make it render well on mobile (hint: it
doesn't). Fix, push, ship.

## Diagnosis
`cruise-propulsion/` is a Design-Canvas (DC) export: every style lives in an
inline `style=""` attribute and the file shipped with **zero responsive media
queries**. On a real 390px viewport that produced:

- **Hero intro set one word per line.** The header grid
  `minmax(0,1fr) minmax(340px,0.86fr)` starved the prose column to **0px** once
  the 340px-min visual aside claimed its share.
- **Simulator form column collapsed to 13px** (`minmax(250px,0.72fr)` beside two
  flexible columns) — completely unusable.
- Single-line diagram, 3-across card grids, and 5-across metrics never reflowed.
- 32px of sideways scroll from the porthole (a content-box: `width:min(100%,520px)`
  + 22px padding + 2px border = 100% + 48px; desktop's layout gap hid it, a phone
  had nothing to absorb it).
- Sticky nav wrapped to two rows and held ~200px of an 844px screen hostage.
- Range sliders 16px tall, nav links 35px — below the 44px touch target.

## Fix (`cruise-propulsion/index.html`, +80/-9)
All additive, all reversible:
- One responsive `<style>` block in `<helmet>`, everything inside `@media
  (max-width:900px)` / `(max-width:640px)`. `!important` is load-bearing here —
  an inline style attribute outranks any external selector, so it's the only way
  to reflow a DC export.
- Added class hooks (`pagenav`, `plant-grid`, `sim-grid`, `cards-3`, `scroll-x`)
  to grid/scroll containers. **No inline style was modified**, so desktop is
  bit-for-bit unchanged by construction.
- `#porthole{box-sizing:border-box}` kills the 32px overflow (rivet ring reads
  clientWidth, which shrinks in step, so decoration stays aligned).
- Wide-by-design content (820px tables, 1000px single-line diagram) scrolls
  inside its card via `.scroll-x`; the diagram gets a 760px legible floor.

## Verification — the real story of this task
Built a CDP mobile oracle (`tools/mobile-audit.mjs`) because
`chrome --window-size` lies (clamps to 500px; lessons_learnt 2026-07-02). It
drives Emulation.setDeviceMetricsOverride for a true narrow viewport and reports
document overflow (ignoring overflow-x:auto scroll containers), crushed grids,
and sub-44px touch targets.

**Two harness bugs nearly sent me down two wrong root causes.** I twice
"concluded" the CSS broke the DC template compiler (once blaming quoted attribute
selectors, once `box-sizing`). Both were false — flake:
1. **Leaked Chrome.** `chrome.kill()` only kills the launcher on Windows; the
   renderer children survive, hold the debug port, and a derived debug port
   (`9333 + pid%400`) then *attached to a stale browser*. Fix: OS-assigned free
   port + `taskkill /T /F` on our own pid tree only (the box had 96 of Arthur's
   real Chrome processes running — never blanket-kill chrome.exe).
2. **Racy boot check.** The guard sampled DC-registry once at a fixed 2.5s; under
   load the boot chain (inject React → compile a big template → paint) runs
   longer, so it emitted false "did not boot" verdicts that looked exactly like a
   regression. Fix: poll for the ready *condition*, not a fixed delay.

Only after both fixes did results go deterministic. The isolation test then
showed cleanly: `box-sizing:border-box` drops scrollWidth 422 → 390 (exact
viewport), page boots with all 530 elements every run. Lesson relearned: never
trust a single run; a flaky oracle manufactures phantom root causes.

Final matrix (all 0px overflow, 0 sub-44px targets on mobile, 530 elements):
360 / 390 / 414 / 768 / 1440. Desktop 1440 keeps 5-col metrics, 3-col cards, and
its original mouse-sized controls (touch rules are ≤900 only).
