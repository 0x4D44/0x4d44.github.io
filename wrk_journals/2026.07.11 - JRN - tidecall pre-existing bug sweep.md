## Scope decision (lead call, kickoff)

In scope — clear defects:
- **A (HIGH)** — round-recap / match-end modal reopens itself when dismissed via ✕ or
  the scrim, replaying `modal-in` and (match path) re-firing the win sound + confetti.
- **B (LOW)** — `celebrate()` has no lock; overlapping confetti loops `clearRect` each
  other every frame and strobe.
- **C (MEDIUM)** — the ≤560px `.table-column` min-height subtracts a hard-coded 64px of
  chrome, but the real chrome above/below it is 73px, so the board overflows ~9px and the
  page scrolls on a phone.
- **D (latent/LOW)** — the face-card J/Q/K/A watermark never renders: the CSS
  `content: attr(data-face)` on `.card-art::before` resolves `attr()` against `.card-art`,
  but the JS writes `data-face` on the `.playing-card` button. Fix only if it looks right
  once rendered; else park (turning on a never-seen visual is a design call).

Parked — not a defect:
- The ~40px exposed tap-strip at 7–8 cards is a touch-UX **enhancement** (needs a
  tap-to-raise interaction change), not a bug. Offered as a follow-up, not taken here.

Also flagged, dead code (cleanup, not bugs): unused `@keyframes active-dot`; `--rot`
declared on the `.slot-*` rules but always shadowed by the inline value `renderTrick`
sets. Fold into a final chore commit.

### Diagnosis + skeptic outcome

The skeptic phase hit a **session limit** mid-run — 4 of 12 skeptics never returned.
Per the rule, a missing vote is UNVERIFIED, never a pass. Subagents are blocked until
14:30 (Europe/London); rather than idle for hours I closed each finding with the
**behavioral repro as a machine-checkable oracle** (fails before the fix, passes after)
plus my own lead code-verification. Where a skeptic *did* return, I incorporated it:

- **D (watermark)** — CONFIRMED 3/3. Root cause: `createCardElement` writes `data-face`
  on the `.playing-card` button, but `.playing-card.face-card .card-art::before`'s
  `attr(data-face)` resolves against `.card-art`, which has none → empty content. Fix:
  write the attribute onto `.card-art`. No CSS change.
- **A (modal reopen)** — 1/3 returned (not refuted); 2 rate-limited. The returned
  diagnosis confirms the two-part cause: `handleModalClick` (app.js:1033) and a
  **redundant** direct listener set (app.js:1098) both call `closeModal(true)`
  unconditionally; `closeModal`'s resume runs `render(); drive()`, and `drive()`
  re-opens the round/match modal because the phase is still at its boundary. The
  Escape path already guards (`!['round','match']`). Fix: guard the delegated close AND
  delete the redundant listeners (they only ever bound the two static elements, which
  already bubble to the delegated handler), and hide the ✕ for round/match. Verified by
  behavioral repro.
- **B (confetti)** — 2/3 returned; the CORRECTNESS skeptic **refuted my symptom
  wording** and is right: two rAF loops on one canvas composite once per frame in fixed
  order, so it is NOT a strobe/half-density. The real symptom: an overlapping *earlier*
  burst is fully erased by the later loop's per-frame `clearRect`, a zombie loop wastes
  CPU, and the `canvas.width=` reset on the 2nd call flashes the bitmap. Root cause (no
  single owner of the shared canvas) and the fix (one cancellable rAF handle) are
  endorsed. Symptom wording corrected here and in the commit.
- **C (overflow)** — 2/3 returned; the COMPLETENESS skeptic **refuted "≤560 only"**.
  The same understated-chrome-constant defect scrolls the board at every game-screen
  tier: ≤560 (styles.css:681, const 64 → +9), ≤820 (line 663, const 90, and it also
  omits the safe-inset subtraction → +11), desktop/base (line 431, const 94 → +12). My
  earlier layout matrix independently measured exactly +9 / +11 / +12. One root cause,
  three manifestations → fixed as one unit, each constant set to the measured-correct
  value and verified to zero the scroll.

Fable 5 not engaged — the B mechanism question was fully resolved by the returned
skeptic (rAF ordering; one composite per frame); nothing here is an elusive/high-leverage
call.
