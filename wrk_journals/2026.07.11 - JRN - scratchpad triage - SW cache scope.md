## The actioned fix — SW cache scoping (commit 4edad5f)

Cache Storage is per-origin, so every almanac PWA shares one namespace. Nine sibling
service workers deleted every non-own cache key on `activate`, wiping siblings'
offline caches on each update. The scratchpad named four (salient/focus/pylos/quarto);
a grep found the same pattern in nine as more apps shipped: + quixo, morning-run,
midi-observatory, japanese-wordle, japanese-travel-rpg. (med-cruise,
humanity-retention, shipshape were already prefix-scoped — used as the reference.)

Fix per file: add a per-app `PREFIX` const and guard the filter
`keys.filter(k => k.startsWith(PREFIX) && k !== CACHE)`. A partial fix wouldn't
resolve the observation — an unfixed sibling still wipes the fixed ones — so the
correct fix covered the whole class.

**No cache-version bump:** an SW-*logic* edit changes the script bytes, so the browser
installs a new SW and runs the new `activate` on next visit; the version string only
gates asset re-caching, and assets are untouched. japanese-travel-rpg's cache name
(`nihon-quest-v3`) is preserved, so its self-check still passes.
