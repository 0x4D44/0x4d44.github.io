# Onu personalities, Flip, and Chaos — journal

## 2026-07-11 — understanding and first design

- Started an isolated task worktree from `origin/main`; the main clone remains
  a clean trunk mirror.
- Read the current `onu/index.html`. It is a single 1,201-line document with DOM,
  async sequencing, rules, deck data, AI, rendering, and audio in one script.
  Snake identity currently affects only name and hue.
- Verified Onu Flip against Mattel's GDR44 English rulesheet. The important
  implementation detail is physical pile reversal: after a Flip, the played
  Flip card becomes the bottom of the discard and the old discard bottom becomes
  the new active top face.
- Could not verify a stable official product called "UNO Chaos". Proposed a
  fixed Onu Chaos bundle matching Ubisoft's documented house rules: Stacking,
  7-0, Jump-In, and Draw-to-Match. Marked this as a sign-off assumption.
- Chose a narrow extraction: pure mode/rule/AI functions in `engine.mjs`, with
  the existing HTML retaining stateful browser sequencing and animation. This
  gives tests a clean seam without introducing a framework or full reducer.
- Wrote the first HLD with explicit rules, file impact, acceptance criteria,
  decisions, and residual risks. No shipped code changed.

## 2026-07-11 — adversarial review and refutation

- Ran three independent read-only reviews: rule correctness,
  architecture/testability, and product/accessibility. Each reviewer then
  received the other two reports and tried to refute every finding.
- Surviving issues were concentrated at interaction boundaries: last-card
  challenges, W4 stacks, 7-0 winner ownership, action-card Jump-In, Onu catches,
  draw-until exhaustion, and reset while an async prompt/timer is live.
- Narrowed the architecture to one pure command transition boundary. The browser
  still owns presentation and timing, but no longer reimplements hands, piles,
  turns, penalties, or winner state.
- Added a compact stack transition table, serialized reaction order, hand-bound
  Onu declaration, final-card semantics, finite draw-until behavior, and one
  real browser/CDP acceptance drive.
- Added explicit keyboard/dialog/live-region/mobile-layout contracts and ensured
  every snake has a cross-mode bias.
- Rejected or did not count claims that failed refutation: exact simulation
  counts, mandatory duplication of personality tells, an alleged absence of
  starter Flip authority, and an unverified separate swap-target export.
- No shipped code changed. The HLD remains `AWAITING SIGN-OFF` pending the
  different-family review and Arthur's explicit approval.

## 2026-07-11 — external design review

  animations, new-match modal exclusion, table-level no-progress redeal,
  probabilistic personality tests, starter Flip wording, live announcements,
  and transferred one-card Onu immunity.
- No significant external item was rejected. Narrowed the proposed reaction
  arbiter because deck multiplicity removes the race it was meant to solve.
- The design is ready to commit and present for Arthur's explicit sign-off. No
  shipped code has changed.

## 2026-07-11 — implementation

- Added a seeded pure command engine with authoritative hands, piles, turns,
  pending penalties, winner state, and invariants. The direct suite covers the
  exact Classic and Flip decks, all three modes, every snake profile, and seeded
  simulations.
- Added a thin browser controller and left `index.html` as the responsive static
  shell. Recorded that file-placement refinement in the HLD; it does not change
  the signed-off architecture or add a build step.
- Added semantic mode, card, prompt, reaction, and personality controls. Dialogs
  trap and restore focus, status remains live, and new-match cancellation settles
  old timers and pending reactions.
- Added dependency-free static and Chrome/CDP acceptance tests. The browser drive
  boots Classic and Flip, cancels Chaos, exercises keyboard controls and dialogs,
  and checks 360x640 and 390x844 layouts.
- Wired the Onu engine, static, and browser suites into the repository test gate;
  wired static validation into the build gate. No dependency or version-bearing
  file was introduced.
- Scoped validation is green: 26 engine tests, 41 static checks, syntax checks,
  and the two-viewport browser acceptance drive.
