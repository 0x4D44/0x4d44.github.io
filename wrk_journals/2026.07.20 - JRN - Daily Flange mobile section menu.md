# Daily Flange mobile section menu

## Goal

Make the long mobile section list usable. The existing desktop overflow menu was
being reused on narrow screens as an unbounded absolute list, so the lower links
fell below the viewport and the panel did not own a scroll context.

## Decision

- Keep the measured desktop `More` overflow behavior.
- On screens up to 760px, collapse all sections behind one labelled `Menu` button.
- Render that list as a full-width sheet beneath the sticky nav, bounded by the
  actual nav bottom and viewport height, with `overflow-y: auto` and overscroll
  containment.
- Keep the existing grouped section headings so the drawer remains scannable.

This follows the common mobile navigation-drawer pattern. Android's layout guidance
uses a drawer for more than a few destinations, while PatternFly distinguishes an
overflow menu for a small number of secondary actions from an expandable section
for larger content sets.

## Validation

- `news/tests/validate-static.mjs` passes.
- `news/tests/browser.test.mjs` uses Chrome CDP at 390x844 and 1280x900. It checks
  real touch hit-testing, the mobile label, no horizontal overflow, a scrollable
  panel whose bottom stays within the viewport, retained section links, and the
  desktop `More` label.
- The browser test was run directly and passed after the first run exposed the
  initial-height edge case; the final implementation derives the sheet height from
  the current nav bottom.
