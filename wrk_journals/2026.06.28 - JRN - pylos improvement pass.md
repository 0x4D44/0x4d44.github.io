## Context
"How do we improve Pylos?" → ran a 6-lens verified review (AI, rules, UX, visual,
code, a11y; 12 agents, each finding adversarially re-checked against the source).
Then started executing the roadmap.

## Key finding from the review
Pylos sits roughly where Quarto did *before* its minimax + test-harness upgrade:
- AI is **1-ply greedy** (`aiPlay`/`evalAfter`), non-deterministic (`Math.random`
  in the eval), only two real tiers, and the "EXPERT" button is that same greedy
  heuristic. No parity/tempo term — the heart of Pylos.
- **No separated engine, no tests.** Rules + AI + render + gestures are one
  ~580-line class. The rules themselves are **correct** (faithful Pylos; the
  "reserves>0 but no legal move" case is provably impossible) — they're just
  unproven.
- Smaller: HINTS label bug, win styled same as loss, no reduced-motion, no live
  region, faint-text contrast, unused fonts, raise has no touch affordance, the
  move log is built but never shown.

## Decision: un-bundle to editable source
The repo only had the 900 KB compiled bundle. Discovered (verified in-browser)
that the design-canvas source — `Pylos.dc.html` + `support.js` (a client-side
runtime) — **runs directly over HTTP, no build step**. So I replaced the bundle
with that readable form (PWA head merged back in). Now the Component class is
directly editable/testable in-tree, and it's *lighter* (~98 KB vs 900 KB).
- Trade-off: ships `support.js` (the design-canvas runtime) as a served file, and
  diverges from the almanac's standard React-in-browser `.jsx` pattern. Fully
  reversible (it's on a branch). Alternative not taken: a full React port (like
  Quarto) — much bigger, only worth it for exact convention parity.

### Verification notes
- A cache-first service worker served a **stale** index.html on reload — had to
  unregister the SW + clear caches in DevTools to see edits. Lesson: bump the sw
  cache version on every shipped pylos change (done: v3), and clear the SW when
  locally verifying.
- Win/loss modal: the custom DC runtime doesn't expose the component instance for
  state injection, and forcing a real win needs a full game, so the modal styling
  is verified by (a) clean zero-error load (winCol is evaluated every render) and
  (b) an isolated logic check of all four end-states. Not pixel-confirmed.
