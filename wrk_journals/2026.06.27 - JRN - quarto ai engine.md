## Understand (done)
- `quarto/quarto-engine.jsx` is pure logic on `window.QuartoEngine`. Today
  `aiChoosePlacement`/`aiChooseGift` are one-ply for both medium & hard
  (take immediate win; avoid moves/gifts that let the opponent win next move;
  else random). 'hard' === 'medium'. A 2-ply fork beats it ~97%, never loses.
- AI runs synchronously inside index.html's "thinking" setTimeout. 'hard' also
  backs the Hint button (`aiChoose*(game,'hard')`) → must be strong AND fast.
- UI has exactly 3 fixed levels (easy/medium/hard). No node/deno/bun present →
  tests run in-browser against the loaded engine.

## Decisions confirmed with Arthur
- Ladder: **bump medium too** — easy=random, medium=shallow search, hard=deep.
- Hard target: **solid & snappy** — depth-bounded + time budget (<~250ms/move),
  avoids forced losses, takes wins, sets forks; mostly draws vs perfect play.

difficulty = search params. Keep `aiChoose*` API unchanged → no caller/UI churn,
Hint improves for free. Inject RNG for deterministic tests. Bump sw.js cache.
