    A

    Architecture

    The contract software can observe: registers, flags, address translation, instruction encodings and exceptions. A Pentium 4 still promises to execute old 8086 code, subject to mode and platform constraints.

    µ

    Microarchitecture

    The private method used to honour that contract: queue, pipeline, dual issue, micro-operations, renaming, predictors and caches. It may change completely while the bytes remain valid.

    Si

    Implementation

    Process node, transistor budget, package, clocks, bus and cache sizes. “Pentium III” spans implementations whose cache and manufacturing details differ while sharing a core lineage.

    1978

    Compact CISC

    One-byte opcodes do a remarkable amount of work. Direction and width bits are sometimes embedded in the opcode itself; ModR/M selects register and memory forms.

    1985

    Escape and override

    The 386 uses 0F as a second opcode map, adds FS/GS, 66/67 size overrides and SIB. Sixteen- and thirty-two-bit code share one grammar.

    1997–2000

    Prefixes become selectors

    MMX, SSE and SSE2 reuse opcode maps. Legacy bytes such as 66, F2 and F3 can become mandatory parts of a new vector opcode rather than ordinary overrides.

    No prediction

    Sequential prefetch continues until a taken transfer proves the next bytes useless. The queue is discarded and refilled at the target.

    Pentium

    Remember targets

    A branch target buffer lets the front end recognise a branch at fetch time and pursue a remembered path early.

    P6

    Speculate deeply

    Prediction now feeds an out-of-order window. Correct guesses expose more parallelism; wrong guesses discard a larger cloud of µops.

    Pentium 4

    Trace the predicted path

    The trace cache stores decoded µops in execution order across taken branches. Prediction helps decide which trace is useful.

    07 · Cycles

    One number stopped being enough.
    That is the story.

    Early manuals can quote an instruction in clocks under explicit assumptions. Superscalar and out-of-order cores need at least latency, reciprocal throughput, µop count, dependency shape, prediction and cache state.

    This deliberately simple model exposes interactions; it is not a benchmark or product performance claim.

    Latency

    Clocks from an operation starting until a dependent operation may consume its result.

    Throughput

    How often another independent operation of that class may begin once the machine is flowing.

    µops

    The number and kind of internal operations a visible x86 instruction becomes. One mnemonic may occupy several resources.

    Retirement

    The rate at which completed speculative work becomes architectural history in original program order.

      Caveat A

      “Pipeline depth” is a counting convention.

      Manufacturers and analysts may count different boundaries. This site uses Intel's launch description of a twenty-stage Pentium 4 pipeline and treats the shorter diagrams as conceptual stage groups.

      Caveat B

      Clock counts need assumptions.

      Manual timings commonly assume prefetched instructions, aligned operands, cache hits or no bus wait states. The ledger repeats those assumptions and avoids comparing unlike numbers as if they were benchmark results.

      Caveat C

      Predictor internals are not all public.

      The predictor lab teaches static, last-outcome, two-bit and history-based mechanisms. It does not assert that its tiny tables exactly reproduce a particular commercial part.

      Caveat D

      Compatibility is not identity.

      Later processors preserve a great deal of earlier software-visible behaviour, but modes, undefined flags, timing, undocumented instructions, platform hardware and errata prevent “the same processor, only faster” from being literally true.

      The deepest continuity is not a pipeline or cache.

      It is the promise that yesterday's bytes still mean something—while tomorrow's machine is free to discover a better way to make them true.
