01 · THE WIRE

One cable, everyone shouting

Ethernet began in 1973 at Xerox PARC as a single coaxial cable that every computer tapped into. Anyone could talk at any time, and anyone could hear everything. That is not a recipe for good manners, so Bob Metcalfe’s design added a few: listen before you talk (carrier sense), listen while you talk (collision detection), and if you hear a clash, stop, wait a random time and try again.

The wait is the clever part. After the first collision each station picks a random slot from 0–1; after the second, 0–3; then 0–7, and so on, doubling up to 1023. Two stations rarely keep picking the same number, and crowds thin themselves out automatically. This is CSMA/CD, and it is a cousin of the exponential backoff your own TCP stack uses when the network is congested.

Why you can mostly forget this. Modern Ethernet is full-duplex: each link is one point-to-point cable with separate transmit and receive pairs, so nothing can collide, and CSMA/CD is switched off. What survived is the frame format and the addressing — and that has barely changed since 1980, scaling from 10 Mb/s to 800 Gb/s.
02 · THE FRAME

A letter with a very strict envelope

Everything on Ethernet travels as a frame. Layer 2 does not know what is in the envelope; it only knows who it is from and who it is for. The addresses are 48-bit MAC addresses, usually written as six hex bytes. At the end, a 32-bit checksum lets the receiver detect damage.

Below is a real, live-built frame. Click any field to see what it does and where its bytes sit. Tick the VLAN box to insert an 802.1Q tag, then flip a bit in transit and watch the checksum catch it.

Payload size. The classic maximum payload is 1500 bytes — the MTU. Frames run from 64 to 1518 bytes (1522 with a VLAN tag). The 64-byte floor exists so a sender is still transmitting when a collision from the far end of the wire arrives; the 1500-byte ceiling was a 1980s memory and fairness compromise. We will break that rule in chapter 7.
03 · SWITCHING

The switch that learns by eavesdropping

A hub repeats every bit out of every port: it is the shared coax in a box. A switch is smarter, and it needs no configuration to be. It keeps a table mapping MAC address to port, and fills it purely by watching source addresses go by.

The rules are three lines: (1) note which port each source MAC arrived on; (2) if the destination is in the table, send it out that port only; (3) if it is unknown, or is a broadcast, flood to every other port. Entries age out after a few minutes, so a laptop that moves does not stay lost.

Loops. Because flooded frames carry no hop count (unlike an IP packet’s TTL), a cable loop between switches makes them circulate forever and multiply — a broadcast storm that can take down a building in seconds, and also makes MAC tables flap as the same source appears on two ports. Spanning Tree Protocol exists to elect a root switch and block just enough links to keep the topology a tree, re-enabling a blocked link only if another fails.
04 · VLANS & TAGGING

Many networks, one set of cables

Floods are the price of switching: every broadcast reaches every port. A VLAN carves one physical switch into several virtual ones, each its own broadcast domain. Staff, guests and cameras can share the same hardware and never hear each other’s broadcasts — or traffic.

Hosts plug into access ports, each assigned to exactly one VLAN, and know nothing about it. Between switches runs a trunk: one cable carrying many VLANs at once. To tell them apart on that shared cable, the sending switch inserts the 802.1Q tag (the 4 bytes from chapter 2) with the VLAN ID — plus 3 priority bits (PCP, used for QoS) and a drop-eligible bit — and the receiving switch removes it before delivering to the access port.

Crossing VLANs. Two VLANs are two separate networks; getting from one to the other needs a router (or a layer-3 switch). That is a feature: it is where you place firewall rules. Providers can stack a second tag on top (QinQ, 802.1ad) to carry a customer’s VLANs across their own network. Also worth knowing — one VLAN on a trunk can be the “native” one, sent untagged; mismatching it between two ends is a classic misconfiguration.
05 · IP, ARP & ROUTING

MACs are for neighbours; IPs are for the world

A MAC address says which card on this wire; it has no geography. An IP address says which network, then which host, and that structure is what lets routers forward packets across the planet with tables of about a million prefixes instead of billions of hosts.

Before sending, a host asks one question: is the destination in my subnet? It ANDs the address with its mask. Same network → ARP (“who has this IP?”, broadcast on the LAN) and deliver straight there. Different → send to the default gateway, which is just a router’s MAC address on the same LAN. At each router the Ethernet frame is torn off, the TTL is reduced, the destination is looked up (longest prefix match) and a new Ethernet frame is built for the next hop.

So: IP addresses stay the same end to end; MAC addresses change at every hop. Step through it.

06 · DNS

The phone book with no front cover

Humans type www.example.com; routers only understand numbers. DNS bridges them with a distributed, hierarchical database. No one server knows everything. The name is read right to left: the root knows who runs .com; the .com servers know who runs example.com; that zone’s authoritative server knows the actual address.

Your device does not do that walk. It asks a recursive resolver (your ISP’s, or 1.1.1.1, or 8.8.8.8) over UDP port 53, and the resolver does the legwork and caches everything, each record for its TTL. That is why the second lookup is nearly free, and why DNS changes can take time to “propagate”: you are waiting for caches to expire.

Try this. Resolve www.example.com (cold: root, TLD, authoritative). Resolve mail.example.com — it skips straight to the authoritative server. Resolve a different .com name — only the root is skipped. Then press +60 s a few times and re-resolve the first name after its 300 s TTL expires.

DNS is plain text by default, so anyone on the path can read and forge it. DNSSEC adds signatures to prove answers are authentic; DoH / DoT encrypt the query to the resolver. Large answers outgrow UDP and fall back to TCP — a quiet reminder that protocols are glued together by fallbacks.

07 · MTU & JUMBO FRAMES

Why nine thousand bytes is a controversy

Every frame pays a fixed toll: 8 bytes of preamble, 14 of header, 4 of checksum, a 12-byte idle gap, and 40 more for IP and TCP headers. At 1500 bytes of MTU that is about 5% overhead. Bigger frames spread the toll thinner — but the larger gain is for the computers: each packet costs an interrupt, a trip through the kernel and a lookup, so a 9000-byte jumbo frame means roughly six times fewer of them for the same data. That is why storage networks and data-centre backbones love jumbo frames. (Offloads like TSO and GRO already batch packets inside the NIC, which blunts part of the gain — measure before assuming.)

The catch: every hop must agree

The MTU is per link. A jumbo frame that meets a 1500-byte link must be fragmented or dropped. Routers fragment IPv4 packets only if the sender allowed it; most modern stacks set the DF bit and rely on the router replying with an ICMP “fragmentation needed” message so the sender can shrink — Path MTU Discovery. When a firewall blocks that ICMP, you get a baffling failure: pings and logins work, big downloads hang.

Rule of thumb. Enable jumbo frames only inside a network you control end to end, set every device on the path (including switches and VLANs) to match, and test with ping -M do -s 8972 host on Linux (8972 + 28 bytes of headers = 9000). Tunnels and VPNs steal bytes — which is why you see MTUs like 1420 or 1400.
08 · TCP, NAGLE & DELAYED ACK

When two good ideas make 40 ms of nothing

Ethernet and IP deliver packets and shrug; TCP turns that into a reliable byte stream. It is also where tiny writes become a problem. Typing one character into a remote shell would send a 41-byte header-wrapped packet for 1 byte of data. In 1984 John Nagle proposed a fix: if there is unacknowledged data in flight, hold new small writes and send them together when the ACK comes back. One tiny packet in flight at a time; the network is never flooded with them, and on a slow link the batches get bigger automatically.

On the other side, TCP receivers use delayed ACK: instead of acknowledging every segment immediately, wait up to ~40 ms (Linux) or 200 ms (some stacks) in the hope of piggy-backing the ACK on a reply, or ACKing two segments with one packet.

Each is sensible alone. Together: a program writes a small header, then its body, then waits for a reply. Nagle sends the header and holds the body until the header is ACKed. The receiver holds the ACK waiting for more data. “Small” here means less than one full segment (the MSS, about 1460 bytes), and the stall needs this write-write-read pattern: if the second write fills a segment, or the receiver has data to send back, nothing waits. Otherwise nobody moves until the delayed-ACK timer expires. Run it below, then switch either feature off.

The fix. Best: write the request in a single call (build the buffer, then send once). Otherwise set TCP_NODELAY on the socket, which disables Nagle — nearly every latency-sensitive client (HTTP libraries, databases, RPC frameworks) does so. Linux’s TCP_QUICKACK addresses the receiver side (and a fresh Linux connection starts in quick-ACK mode, so the stall tends to appear a few round trips in). Keep Nagle on for bulk transfers and interactive tools on slow links, where it earns its keep.
09 · RECAP

The whole journey, in one breath

  1. DNS turns www.example.com into an IP address, with caching at every layer.
  2. TCP chops your data into segments no larger than the MSS (MTU − 40), with Nagle and delayed ACK deciding when the small ones go.
  3. IP asks “is that in my subnet?” and picks a next hop, via ARP for its MAC.
  4. Ethernet wraps it in a frame — dst MAC, src MAC, optional VLAN tag, type, payload, CRC.
  5. A switch learns MACs and forwards within a VLAN; a trunk carries tagged frames between switches.
  6. A router strips the frame, decrements TTL, matches the longest prefix and builds a fresh frame for the next link. Repeat until delivered.
MAC address
48-bit link-layer address; meaningful only on one LAN.
Broadcast domain
All devices that receive each other’s broadcasts. One VLAN = one broadcast domain.
Access / trunk port
Untagged single-VLAN port for hosts / tagged multi-VLAN port between switches.
ARP
Resolves an IPv4 address to a MAC on the local link. (IPv6 uses Neighbour Discovery.)
TTL
Hop budget in the IP header, cut by one per router, preventing eternal loops.
MTU / MSS
Largest IP packet a link carries / largest TCP payload in one segment (MTU − 40 for IPv4).
TCP_NODELAY
Socket option that turns Nagle’s algorithm off.
FCS
Frame Check Sequence: the CRC-32 at the end of a frame.
