## Decisions / assumptions
- `manifest.people.json` = `{ files: [], people: { dir, glb, meta, lod } }`: `files` stays empty so `ctx.assets.preload()` never drags the character GLB in; `rig.js` reads the `people` block. `lod` is now set (people_lod.glb, 1.5 MB).
- Deterministic: all casting/behaviour RNG derives from `makeRng(ctx.seed).fork('people')` (casting: `.fork('cast')`, per person `.fork('life:<id>')`).
- Casting is pure (`js/people/cast.js` + `look.js` + `personas.js`, no THREE) so Node tests import it. `appearance` = `charId|garment variant key`.
- Bank wiring rule (from the Spanish review): persona id == bank key; a bank written AS a woman / man (`lines/genders.js`: vecina abuela maestra enfermera beata / vecino abuelo obrero mototaxista) is only ever cast with that gender; all other banks use `{o|a}`.
- Player gender: `ctx.settings.v.address` ('m' default | 'f') drives `{vecino}{mijo}{señor}{lo}{Bienvenido}...` in `dialogue.js` `fillTokens`; `joven` never changes. (Needs A1 to add the settings select.)
- Speech: `speech.js` never creates/resumes an AudioContext for a script-made event (`e.isTrusted` or `navigator.userActivation.hasBeenActive`); reuses `ctx.audio.context()` when the game has one. Voice rank es-CO > es-MX > es-US > es-419 > es-AR > es-CL > es-ES > other es; language outranks gender (a bug the new test found: a Mexican voice of the "right" gender used to beat a Colombian one).
