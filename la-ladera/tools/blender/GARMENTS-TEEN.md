# Teen garment objects — PR80 layout

The teen library contains 29 original everyday styles in two art sizes, with
162 applicable pose objects and 162 separate LODs. It ports the catalogue,
patterns and fabric artwork from `18a37a7e29888cecc733e16bcd623b21c599916e` onto
child-library base `c4e8f46e8f617896f508728f77cda029ec494e88`. Adult and child
assets, manifests, tests and their builders remain independent.

## Files and generated data

| File or directory | Purpose |
| --- | --- |
| `garments_teen.catalog.json` | Editable 29-style catalogue, source IDs, dimensions, variants and applicable states |
| `garments_teen_build.py` | Original teen geometry, sequential cloth baking, core glTF packing and staged six-pack installation |
| `garments_teen_textures.py` | Deterministic Python standard-library fabric atlas generator |
| `assets/models/manifest.garments-teen.json` | Actual dimensions, triangle counts, hashes, size tags and high/LOD file bindings |
| `assets/models/garments-teen/garments_<state>.glb` | High-detail flat, folded and hung packs |
| `assets/models/garments-teen/garments_<state>_lod.glb` | Separate flat, folded and hung LOD packs |
| `assets/models/garments-teen/teen/palette.json`, `fabrics.png` | The existing original 256×256 teen fabric atlas and palette |
| `assets/models/garments-teen/assortments.json` | Explicit small/big drawer, wardrobe and school-locker recipes |

Paths in the last five rows are relative to `la-ladera/`. Runtime data in
`js/interiors/garments_data.js` is generated by `tools/garments_data.mjs` from
all three manifests and the palettes. The teen loader uses the same per-size
pack bindings introduced for children through an explicit size selection.
Generated records and catalogue entries
retain `sizeTag: 'teen'`, `sizeClass: 'small' | 'big'` and the original `styleId`.
Never edit the generated module directly.

Keys are `garment_teen_<styleId>_<small|big>_<flat|folded|hung>`; LOD node names
append `_lod`. The manifest's `garment` field is `teen_<styleId>_<small|big>`.
Each selected root must be cloned as a whole, including its scaled child mesh.
Do not add the entire pack scene to a room: that would draw every named object
at the same origin. The interior loader selects named LOD roots.

## Rebuild and validate

Run quietly from the repository root with Blender 4.5 LTS or newer and Node
22.16 or newer. On Linux:

```sh
node la-ladera/tests/memgate.mjs 6 300
nice -n 15 blender --background --factory-startup --threads 1 --python-exit-code 1 --python la-ladera/tools/blender/garments_teen_build.py --
nice -n 15 node la-ladera/tools/blender/garments_validate.mjs --complete
node la-ladera/tools/garments_data.mjs > la-ladera/js/interiors/garments_data.js
nice -n 15 node --import ./la-ladera/tests/register.mjs --test --test-concurrency=1 la-ladera/tests/interiors-garments.test.mjs la-ladera/tests/garments.test.mjs la-ladera/tests/garments-teen.test.mjs la-ladera/tests/interiors-garments-teen.test.mjs
nice -n 15 node la-ladera/tests/payload.mjs
```

The standalone teen builder imports utility functions from the unchanged adult
builder. It stages and validates the teen export before installing the teen
directory and manifest, with rollback on a caught failure. The tracked
`assortments.json` and `CREDITS.md` are preserved as inputs. It does not rebuild
or install adult/child files. For isolated work append
`--out /absolute/isolated/models`; `--only style,style` requires an isolated
output directory and cannot overwrite the complete shipped library.

Use `--teen --complete` for an isolated teen validation; `--complete` and
`--all --complete` check adult, child and teen together. Mutation tests make
copies of real assets, damage those copies and invoke the selected acceptance
tests. They use ordinary Node test isolation, including on Node 22.16.

The validator and integration mutation reproduction commands are:

```sh
nice -n 15 node la-ladera/tools/blender/garments_teen_mutate.mjs --json la-ladera/dev/garments-teen/verification/teen-mutations.json
nice -n 15 node la-ladera/tools/garments_teen_integration_mutations.mjs --json la-ladera/dev/garments-teen/verification/integration-mutations.json
```

To reproduce all real-model contact sheets, set `CHROME_PATH` and run:

```sh
CHROME_PATH=/path/to/chrome LADERA_PRIO=idle nice -n 15 node la-ladera/dev/garments-teen/capture.mjs
```

The project's browser harness always launches headless with a private profile
and low priority. A sandbox denial or empty log is not successful evidence.
The capture renders all 162 detailed and all 162 LOD teen objects beside adult
and child tee references. Every card uses the same 3.90 m orthographic camera
width and root scale 1.0. Source hashes, measured dimensions, triangle counts,
visibility and clipping checks appear in `dev/garments-teen/evidence/visual-report.json`.

## Styles, sizes and states

| Family | Styles |
| --- | --- |
| T-shirts | Cream, teal, original geometric sun print |
| Cropped tops | Ribbed sleeveless, boxy short-sleeve |
| Everyday bottoms | Chino shorts, stretch cycling shorts, stretch trousers, denim shorts, straight jeans, joggers |
| Dresses | Short T-shirt dress, knee-length, midi and maxi |
| Outerwear | Hoodie with pocket and empty hood; light jacket with central zip |
| School | Generic white polo, grey/navy jumper, navy/grey trousers and skirt |
| Accessories | Paired socks and structured peaked cap |
| Plain underwear | Full-coverage briefs and boxer shorts |
| Plain swimwear | One-piece swimsuit and swim shorts |
| Footwear | Paired closed school shoes and strap sandals |

| Size class | Approximate age label | Uniform adult-reference pattern scale |
| --- | --- | ---: |
| `small` | 12–15 | 0.70 |
| `big` | 16–19 | 0.90 |

Age labels describe art direction, not a real apparel sizing standard. The
export already contains the .7/.9 child transform, so consumers must not apply
that factor again. The validator measures actual vertex data through node
transforms, verifies the 7:9 small/big extent ratio on all axes, and rejects LOD
envelope drift beyond 5% or 2 mm. Catalogue metadata cannot raise the independent
limits or redefine the required style/state set.

Ordinary soft clothing has folded, hung and flat states. Socks have folded and
flat states; the cap has hung and flat states because its visor is rigid. School
shoes and sandals each have one resting flat pair. There are 52 folded, 52 hung
and 58 flat objects, each with a matching LOD.

## Geometry, textures and budgets

The coordinate contract matches adult and child objects: metres, +Y up, +Z front;
flat/folded items rest at Y=0 centred on X/Z, while hung items descend from a top
support at Y=0. Empty panels have neck, sleeve, waist and leg openings. Cloth is
baked offline and frozen; no body, skin or animation is present.

The port keeps the original patterns, sewn details and LOD shapes. Small and big
objects share core glTF meshes within each pack, with explicit child transforms.
Float32 positions and normals, normalized uint16 UVs and uint8 vertex colours
require no compressed-geometry decoder. Each object has one `laundry` material
primitive. The GLBs embed no images, texture bindings or external buffers.

Adult and child objects continue to share `garments/prints.png`. Teens retain
the existing `teen/fabrics.png` tile atlas; no additional texture page is added.
The preview selects a tile with the palette's top-left 4×4 convention, a two-pixel
inset, white material multiplier and retained vertex colours. The current
renderer can use the tint fallback; the original sun motif requires its tile.

Detailed objects stay at or below 800 triangles; LODs stay at or below 240 and
remove at least 40%. The complete teen runtime directory and manifest must stay
under 3,500,000 bytes, including accidental extra files. Source code and developer
contact sheets are outside that runtime payload. `payload.mjs` retains the
existing 150 MiB shipped and 800 MiB GPU texture gates.

## Explicit loading and placement boundary

The existing page keeps its adult/child default preload and `GARMENT_KEYS`
contract: 124 keys. `ALL_GARMENT_KEYS` exposes all 286 adult, child and teen pose
keys. `garmentKeysFor(['teen'])` returns the 162 teen keys, including both sizes.
An explicit consumer can register or load the teen library:

```js
registerGarmentAssets(ctx, { sizeTags: ['teen'] });
await loadGarmentAssets(ctx, { sizeTags: ['teen'] });
```

The loader fetches only the three teen LOD packs for that selection. To request
all three libraries, pass `{ sizeTags: ['adult', 'child', 'teen'] }`. Calling the
existing API without options retains the adult/child selection. Detailed packs
remain preview assets. The optional loading interface does not change normal
page startup or place clothes in a room.

The teen recipes are selection data for a future explicit teen furnishing pass.
They do not wire new clothes into room, drawer or locker rendering. See
[teen room and school-locker guidance](../../dev/garments/TEEN-PLACEMENT.md) and
[original artwork provenance](GARMENTS-TEEN-SOURCES.md). All designs are plain
original garment objects without real brands, logos or school insignia.
