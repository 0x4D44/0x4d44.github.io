AI coding models · benchmark results

mdbench

A private benchmark that asks which model should hold which seat: who designs, who codes, who writes tests, who reviews, who debugs. It is built from real problems in our own projects, rewound to the moment before they were solved, and it is organised in suites, each with its own scoring. Here are the results so far, with what each run cost and how long it took.

02 · Headlines

Leaderboards

Mean score per seat across a suite's tasks. Each suite measures something different, so the boards are never merged. A mean over a handful of tasks is a coarse signal: read the per-lane tables on each suite page before drawing conclusions.

03 · Seats

The seats

A seat is one model at one effort setting in its usual harness: Claude models in Claude Code, OpenAI models in the Codex CLI. The same model at two efforts is two seats.

Cost basis: Claude Code reports a list-price cost for each run; the Codex CLI reports only tokens, so GPT costs are estimated from tokens at published list prices. Neither is what was paid: runs used subscriptions, except the API baselines.

04 · Read this first

Caveats

  • Small samples. The software suite has ten exercises, two per lane, and one run per seat so far. Differences of a few points are within judge noise.
  • Judges are models: three Claude Opus 5.5 and three GPT-6 Astra. Judging is blind but not fully independent of the Opus and Astra seats.
  • Costs are list-price figures (reported for Claude, estimated from tokens for GPT). A few Claude runs were resumed after a usage limit, which inflates their cost.
  • Speed gates were timed on a machine that was doing other work, as five paired runs.
  • The exercises come from private repositories, so tasks are described here only in outline.

Data generated – from the benchmark's own records. Each suite page has its full methodology.
