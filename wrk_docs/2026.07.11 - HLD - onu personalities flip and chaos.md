# Onu personalities, Flip, and Chaos

**Status:** AWAITING SIGN-OFF  
**Date:** 2026-07-11  
**Scope owner:** Arthur + Codex

## Goal

Turn Onu into a three-mode single-player card game: the existing rules-strict
Classic mode, an official-rules-inspired **Onu Flip** mode, and a fixed
house-rules **Onu Chaos** mode. The ten snake opponents gain visible,
mechanically distinct personalities in every mode.

## Success

- A player can choose Classic, Onu Flip, or Onu Chaos before a match and can
  change mode when starting a new match.
- Classic remains rules-equivalent to the current game.
- Onu Flip implements the 112-card, two-sided Light/Dark rules and scoring
  described by Mattel's Flip rules, with all player-facing branding renamed
  to Onu.
- Onu Chaos is one clear, fixed bundle of four familiar digital house rules:
  Stacking, 7-0, Jump-In, and Draw-to-Match.
- Each named snake exposes a short personality description and makes
  observably different decisions from at least one other snake in controlled
  game states. Personality is strategy, not merely dialogue or delay.
- The rules and AI decisions are deterministic under a seeded random source
  and have direct Node tests; the browser remains a zero-build static page.
- The game remains usable on a 360x640 phone and has no external runtime
  dependency.

## Non-goals

- Online or local human multiplayer.
- Mixing Flip and Chaos rules in one match.
- A custom house-rule editor or individually toggled Chaos rules.
- Show 'Em No Mercy, Party Mania, or an unofficial fan-made "UNO Chaos" deck.
- Saved matches, migrations, feature flags, analytics, or a framework/bundler.
- Perfect or cheating AI. Snakes only use information a human player could
  legitimately use, plus public hand sizes and played cards.

## Rule sources and scope assumption

Mattel publishes an official Flip rulesheet:
`https://service.mattel.com/instruction_sheets/GDR44-English.pdf`. It defines
the 112 faces on each side, pile flipping, action-card behaviour, challenges,
side-dependent scoring, and the first-to-500 match.

There is no official Mattel product or stable ruleset named "UNO Chaos" that
could be verified. This design therefore uses the four house rules documented
for Ubisoft's digital game:
`https://news.ubisoft.com/en-us/article/24Ki6Wct851vIEWkqoKwzy/uno-is-now-compatible-with-playlink-for-ps4`.
They ship together here as **Onu Chaos**, not as claims about official tabletop
rules. This interpretation is a sign-off decision.

## Current shape

`onu/index.html` is a self-contained 1,201-line document. It owns card data,
mutable match state, rules, AI scoring, async animation, modals, rendering,
audio, and the page shell. The current AI has one shared heuristic; snake name
and hue are cosmetic. There are no Onu-specific tests in the root test gate.

The expansion adds enough rule branches that leaving every rule inside the DOM
script would make both correctness and review brittle. A small pure module is
the useful seam; a framework or generic plugin system is not.

## Approach

### 1. Three fixed modes

Add a mode chooser to the opening screen. A mode is selected before cards are
dealt and cannot change mid-match. The header's new-match button opens one
dialog with **Rematch in current mode**, **Change mode**, and **Keep playing**.
Rematch resets scores and draws three new snakes only after confirmation.
Change mode returns to the chooser and resets only after the next mode is
confirmed. Keep playing is the default focused action and changes nothing.

The mode definitions are plain data plus explicit rule functions. They are not
a public extension API:

- `classic`: current 108-card deck, actions, W4 challenge, and scoring.
- `flip`: 112 paired physical cards, active side `light` or `dark`, Flip rules.
- `chaos`: Classic deck/scoring plus the fixed four-rule bundle below.

The header, table status, rules modal, splash copy, card palette, and Officer
Reggie tips reflect the active mode. No player-facing text says "UNO"; the
product and calls are Onu, Onu Flip, and Onu Chaos.

### 2. Pure rule-state core, thin browser orchestration

Create `onu/engine.mjs` for rule logic that does not touch the DOM or timers.
It owns every mutation of rule state through one small command boundary:

```text
transition(gameState, command, rng) -> { gameState, events, request? }
```

Commands cover play, draw, colour/target choice, challenge, stack/accept,
Onu/catch, and Jump-In. A transition may request one human choice; the browser
renders that request and submits the answer as the next command. Presentation
events describe animations and messages. The browser may delay between events,
but it never directly changes hands, piles, colours, turns, pending penalties,
Onu state, or the winner.

Events are presentation-only and need not encode a complete state delta. After
replaying them, the browser always reconciles from the returned `gameState`,
which is authoritative.

The module also exports only the definitions and helpers the page and tests
need:

- mode and snake definitions;
- deck creation and seeded shuffling;
- active-face lookup, matching, legal moves, and card scoring;
- challenge outcomes, draw-stack eligibility, hand swap/rotation, and flip
  transforms used by the transition boundary;
- snake move decisions, including any required colour or swap target, plus
  challenge, Onu-call, and Jump-In decisions.

`onu/index.html` keeps browser interaction state, animations, prompts, sound,
and timing. The command boundary is not a framework or extensibility layer; it
is the narrow guarantee that tested rule ordering is the ordering shipped in
the browser.

Classic extraction is the first implementation slice. Before moving behavior,
add characterization fixtures for its current deck, matching, actions,
challenge outcomes, scoring, and turn order. "Parity" means the current
documented rules, not preservation of the existing last-card W4 bug where the
page marks a winner before a successful challenge puts cards back in that hand.

Randomness is injected as `rng()` into deck and AI functions. Production passes
`Math.random`; tests pass a tiny seeded generator. No global seed control or
environment variable is added.

### 3. Card representation

A physical card has a stable id and one or two named faces:

```text
{ id, faces: { classic: face } }
{ id, faces: { light: face, dark: face } }

face = { color, symbol, points }
```

Classic and Chaos read `faces.classic`. Flip reads the current `state.side`.
The Flip deck builder creates the exact official multiset on each side, then
pairs the two fixed face lists by index. The pairing is stable and tested; it
does not pretend to reproduce Mattel's physical face-to-face pairings, which
the rulesheet does not specify.

Cards render only the active face. Opponents and the player do not inspect the
inactive face, so the AI gains no hidden information.

### 4. Onu Flip rules

Onu Flip begins on the Light side with the official 112-face composition:

- Light: 1-9 in four colours (two each), Draw One, Reverse, Skip, Flip
  (two per colour), four Wild, four Wild Draw Two.
- Dark: 1-9 in pink/teal/orange/purple (two each), Draw Five, Reverse,
  Skip Everyone, Flip (two per colour), four Wild, four Wild Draw Colour.

When a Flip card is played, after it reaches the discard pile:

1. reverse the discard pile, making the played Flip card the bottom;
2. reverse the draw pile;
3. toggle every card's visible side by changing `state.side`;
4. derive the current colour/symbol from the newly exposed discard top.

The newly exposed top card controls matching but does not fire its action; it
was revealed, not played. Reshuffling preserves physical card pairs and the
active side.

Action rules follow the rulesheet:

- Light Draw One; Reverse; Skip; Flip; Wild; restricted Wild Draw Two with a
  challenge (guilty offender draws two; failed challenger draws four).
- Dark Draw Five; Reverse; Skip Everyone (turn returns to the player); Flip;
  Wild; restricted Wild Draw Colour with a challenge. On a successful challenge
  the offender draws through the chosen colour, the challenger draws nothing,
  and keeps their turn. On a failed challenge the challenger draws through the
  chosen colour plus two and loses their turn.
- A last-card penalty action still resolves before round scoring.
- Round scoring uses the face visible when the round ends. First to 500 wins.
- Starter action cards apply their documented setup behaviour; restricted wild
  draws are returned and replaced. A starter Flip immediately reverses both
  piles and toggles the active side so every hand shows its Dark face; hand card
  order itself is irrelevant and is not reversed. The dealer's left then starts.

Every draw-until operation uses one finite helper. It performs the normal
discard reshuffle and stops when no recyclable card remains. If a selected
colour is unreachable, the affected player keeps every card drawn and still
misses the turn; the status explains that the colour was exhausted. A guilty
last-card wild-draw offender is no longer a winner after receiving cards.

### 5. Onu Chaos rules

Chaos deliberately uses the Classic 108-card deck, classic W4 legality, classic
point values, and first-to-500 scoring. Officer Reggie labels it "authorised
anarchy" and the rules screen lists all differences up front.

The fixed bundle is:

1. **Stacking:** a player facing a Draw Two may play another Draw Two; a player
   facing a Wild Draw Four may play another permitted Wild Draw Four. Penalties
   add and pass to the next player. Types do not mix. A restricted wild may be
   bluffed, but remains challengeable against the colour active before it was
   played.
2. **7-0:** playing a 7 requires choosing one opponent and swapping whole hands.
   Playing a 0 rotates all hands once in the current direction. A hand is a
   packet of cards plus whether its one-card state was declared; the Onu state
   moves with that hand. A transfer alone does not invent simultaneous catch
   windows. The effect is mandatory on a final 7 or 0. After transfer, whichever
   seat holds the empty hand wins—even if that means the card player handed the
   win to a snake. A player receiving an undeclared one-card hand is deliberately
   immune from a retroactive catch; they did not create that one-card state by
   playing. This is a Chaos simplification, not a claim about official rules.
3. **Jump-In:** after any non-Wild card is played, another player holding an
   exact visible match (same colour and symbol/value) may play it out of turn.
   Every card's normal effect resolves exactly once before its Jump-In window.
   Thus a Draw Two first penalises and skips its original target; an identical
   jumping Draw Two then acts from the jumper's seat against the next seat after
   the jumper. Skip and Reverse follow the same rule: the first effect remains,
   then the jumping card applies a second effect. The jumper becomes current and
   normal direction continues from that seat.

   After effects and any Onu catch resolve, the browser opens one bounded
   reaction window. A fixed action-bar control shows the matching card and time
   remaining; the ordinary hand card also highlights, and `J` activates the
   jump. Eligible snakes use their profile's reaction probability and delay.
   The timer pauses while the document is hidden or a required game prompt owns
   focus. A monotonic reaction id rejects a stale callback after reset or window
   close. No Jump-In opens while a draw stack is pending or after any seat has
   an empty hand, so a completed round cannot be stolen.
4. **Draw-to-Match:** a player with no legal card draws until a playable card is
   found, then may play that drawn card or keep it. Drawing stops safely if the
   deck cannot produce a card after the normal discard reshuffle.

Wilds cannot Jump-In because colour choice means they are not exact matches.
Draw stacks resolve completely before one Jump-In window opens on the final top
card, preventing two reaction systems from competing for the same turn.

Deck multiplicity bounds the reaction: each coloured 1-9/action face has two
copies, so after one is played at most one other player can hold the exact mate;
each coloured 0 has one copy and is never Jump-In eligible. A successful jump
therefore cannot chain into a second exact jump, and there is no multi-player
reaction race to model.

The pending-stack transition is explicit:

| Pending state | Target response | Result |
|---|---|---|
| Draw Two `N` | stack Draw Two | add 2; next seat becomes target |
| Draw Two `N` | accept/no card | target draws `N`, loses turn; clear stack |
| W4 `N`, latest play unchallenged | challenge | inspect latest offender |
| W4 `N`, latest play unchallenged | stack W4 | add 4, choose colour; next seat becomes target |
| W4 `N`, latest play unchallenged | accept | target draws `N`, loses turn; clear stack |
| challenged W4, offender guilty | — | offender draws entire `N`; target keeps normal turn; clear stack |
| challenged W4, offender innocent | — | target draws `N + 2`, loses turn; clear stack |

Each target gets one ordered choice: challenge the latest W4, stack, or accept.
An intentional W4 bluff is challengeable rule-breaking, not a structurally
invalid engine move.

### 6. Snake personalities

Keep one AI algorithm with profile weights; do not build ten bespoke bots. Each
profile has a player-facing epithet and one-line tell, plus a small set of
bounded behavioural weights:

| Snake | Readable style | Cross-mode mechanical bias |
|---|---|---|
| Cobra | The Striker | spends attacks against a near-out next player |
| Python | The Squeezer | hoards wilds and controls a long colour |
| Mamba | The Closer | sheds high-point cards and takes finishing lines |
| Viper | The Bluffer | risks illegal wild draws and challenges often |
| Boa | The Colourist | maximises future cards in the chosen colour |
| Adder | The Ambusher | favours exact symbol matches; jumps aggressively in Chaos |
| Anaconda | The Accountant | conservative legal play; protects score value |
| Sidewinder | The Dodger | uses skips/reverses to redirect threats |
| Rattler | The Gambler | higher-variance choices and challenges |
| Taipan | The Tactician | values next-player hand size and turn order most |

Profiles tune existing decisions—card score, colour selection, W4 bluff and
challenge, Onu-call reliability, Jump-In reaction, swap target, and whether to
play a newly drawn card. Every profile has at least one bias used in Classic and
Flip; Chaos may add a reaction-specific tell. All weights are clamped and named.
Random noise breaks ties but cannot swamp a decisive profile preference.
Tests of probabilistic biases fix `rng()` at a value between two profiles'
thresholds, so the same controlled state produces different decisions for a
named reason rather than by sampling luck.

The seat shows the epithet; tapping/focusing it reveals the one-line tell. This
makes behaviour learnable without exposing numeric weights. Personality remains
attached to the snake across rounds and resets only when a new match draws a
new pit lineup.

### 7. Turn sequencing and cancellation

One interaction scope extends the existing generation token. Every async helper
captures the generation, checks it after each await and before each transition,
and registers its timer or pending prompt with the scope. Starting a new match
increments the generation, clears registered timers, closes and settles the one
active modal/reaction/UI promise with a cancelled result, and only then rebuilds
state. A reaction window also carries its own monotonic id so same-generation AI
timers cannot outlive their window. The new-match control is disabled while a
required prompt or reaction owns focus, so modal focus traps never stack. No
event bus or task manager is added.

Resolve one play fully before advancing the turn:

```text
submit play command -> core updates discard/colour and requests choices
-> core resolves challenge/stack/hand transfer and mandatory draws
-> serialize Onu call/catch -> determine post-effect winner
-> if non-terminal, one Jump-In window -> advance turn
```

For last-card plays, mandatory draws and hand transfers resolve first. The core
derives the winner only from the resulting state, then uses the active Flip side
for scoring. Catch and Jump-In never remain live together.

If a full lap completes with no card played and no card can be drawn after the
normal reshuffle, the round is void: award no points, advance the dealer, and
redeal the same numbered round. This finite fallback prevents Draw-to-Match or
Draw Colour exhaustion from producing an endless pass loop.

### 8. Browser interaction and layout contract

Cards, piles, seats, colour/target choices, and reaction actions use native
buttons where possible; custom card controls expose a name, button semantics,
Enter/Space activation, and visible focus. Modals use dialog semantics, place
focus on the safe/default action, trap it while open, and restore it on close.
Turn and reaction status is a polite live region.
The Jump-In control announces window open and close assertively once; the visual
countdown is not repeatedly placed in a live region.

The splash and modals scroll within `100dvh`. Mode choices become one compact
column on narrow phones. Opponent epithets stay short; tells use a persistent,
labelled `aria-expanded` disclosure rather than enlarging every seat. The
disclosure is disabled while a reaction window is live.

## Acceptance criteria

1. The opening chooser selects exactly one mode. The new-match dialog has
   Rematch, Change mode, and Keep playing; only a confirmed rematch/mode choice
   resets scores/snakes, and no old timer, prompt, or state survives it.
2. Classic's deck multiset, playability, action effects, W4 challenge, scoring,
   and 500-point match remain covered and unchanged.
3. Flip creates 112 physical cards whose Light and Dark face multisets exactly
   match the official rulesheet.
4. A Flip play reverses both piles, changes every visible face, leaves the
   played Flip card at the discard bottom, and does not execute the newly
   exposed top action.
5. Every Light/Dark action, starter action, both restricted-wild challenge
   branches, last-card penalty, unreachable draw colour, and side-dependent
   score has a deterministic transition test.
6. Chaos tests cover every pending-stack table row, a three-W4 chain, final-card
   challenge, final 7/0 winner identity, 7 swaps, 0 rotations in both directions,
   hand-attached Onu state and transfer immunity, action-card Jump-In ordering,
   one Jump-In after a resolved Draw Two stack, zero's non-eligibility,
   catch-versus-jump serialization, Draw-to-Match exhaustion, and a void/redeal
   after a full no-progress lap.
7. Ten named fixtures—one per snake—exercise every advertised cross-mode bias
   in both Classic and Flip; Chaos adds reaction fixtures. Fixed seeded
   simulations in all modes assert after every command that moves are
   structurally legal and state invariants hold. Restricted-wild bluffs are
   separately asserted as permitted, challengeable behavior.
8. All mode and rule names visible in the game say Onu. The rules screen clearly
   labels Chaos as house rules and explains all four additions.
9. Keyboard and touch users can choose a mode, play/draw, choose colours/swap
   targets, challenge, stack, catch, and Jump-In. Dialog focus returns correctly;
   status is announced; reaction timing pauses while hidden or prompt-focused.
10. At 360x640 and 390x844, the browser drive proves no horizontal page scroll,
    no clipped required control, and successful hit-testing/activation for mode,
    hand, prompt, Jump-In, and personality-disclosure controls.
11. `onu/index.html` has no duplicate ids or missing local assets, contains no
    external runtime URL, and its module boots without console/page errors under
    headless Chrome. The browser drive also resets during an AI delay and draw
    animation to prove cancellation, and proves the new-match control cannot
    stack over a required prompt/reaction.
12. Root `npm test` and `npm run build` include Onu and pass cleanly.

## Decision log

- **Modes are exclusive.** Combining Flip's two-sided deck with Chaos reactions
  multiplies ambiguous interactions without serving the request.
- **Chaos is a fixed Ubisoft-style bundle.** There is no verified official
  "UNO Chaos" specification; fixed rules keep the promise understandable and
  testable.
- **Extract a pure module, not an app framework.** The rule surface needs tests;
  the command boundary owns rule state while rendering and animation stay local.
- **Use profiles, not ten algorithms.** Shared legal-move generation prevents
  personality code from inventing illegal play paths.
- **Pair Flip faces deterministically.** Exact physical pairings are not present
  in the official rulesheet and are not required for rules-correct play.
- **Keep real-time Jump-In serial.** A single reaction window preserves the
  fantasy without allowing timer races to mutate state concurrently.
- **Exploit deck multiplicity.** There is at most one exact-match candidate and
  no possible jump chain, so reaction handling stays single-candidate and lean.
- **Resolve effects before Jump-In.** Each card acts once from its own seat;
  action-card jumps are a second play, not a retroactive cancellation.
- **Move Onu declaration with the hand.** This makes 7-0 transfers deterministic
  and avoids inventing simultaneous catch obligations.
- **No mid-match persistence.** It adds schema and timer restoration problems
  unrelated to the requested modes.

## Residual risks before implementation

- The meaning of "Onu Chaos" is a product decision, not an established ruleset;
  the four-rule interpretation needs Arthur's explicit sign-off.
- Flip's fixed face pairing will be internally consistent but may differ from a
  retail deck. No authoritative pairing table has been found.
- Jump-In introduces time-sensitive interaction. The fixed action-bar control,
  keyboard shortcut, and pause rules reduce, but do not eliminate, accessibility
  pressure.
- Moving rules out of the inline script touches the current Classic path. The
  parity tests must land before the extraction and remain the regression oracle.

## Review record

### Adversarial review and cross-refutation

Three independent reviews covered rules, architecture/testability, and product/
accessibility. Each reviewer then checked the other two reviews against the HLD,
current code, and cited rules. The following findings survived refutation and
are folded into this revision:

- rule-state ordering must be testable at the command boundary; terminal state
  cannot be set before mandatory challenges/draws/transfers;
- generation alone does not cancel pending prompts/timers, and a reaction id
  must reject callbacks after their window closes;
- W4 stack/challenge transitions, final 7/0 ownership, Draw Colour exhaustion,
  action-card Jump-In ordering, and catch-versus-jump priority needed exact rules;
- Classic needs characterization before extraction, and browser-only acceptance
  needs one real CDP drive rather than static assertions;
- narrow-phone overflow, semantic controls/dialog focus/live status, and a fixed
  visible Jump-In affordance needed explicit acceptance;
- every snake needs a cross-mode mechanical bias, not a Chaos-only identity;
- the rematch/change-mode interaction needed one exact flow.

Refuted findings: fixed AI simulation counts were implementation tuning; the
personality disclosure already allowed a persistent accessible implementation;
and the cited Flip rulesheet already governs starter actions. A claimed missing
swap-target export remained unverified because it can be part of the move
command; the HLD now clarifies that secondary choices are seeded without
counting that claim as a survivor.

### External review

A single read-only Claude/Opus pass found no critical blocker. It confirmed the
command core was lean and the revised Flip, stack, winner, catch, cancellation,
and accessibility rules were internally coherent. Its useful findings were
folded in:

- a draw stack now resolves fully before the final top card gets one Jump-In
  window;
- exact-card multiplicity makes zero unjumpable, limits every window to one
  possible candidate, and makes chained jumps impossible;
- the browser reconciles authoritative state after presentation events;
- the new-match dialog cannot stack over a required prompt/reaction;
- a full no-progress lap voids and redeals the round;
- probabilistic profile fixtures use threshold-bound seeds;
- starter Flip wording, reaction announcements, and transferred one-card Onu
  immunity are explicit.

No significant finding was rejected. One recommendation was narrowed: a
multi-contender first-result arbiter is unnecessary because the physical deck
permits at most one exact mate; the reaction id remains for cancellation safety.
No second review round ran because there was no critical finding.
