## API (frozen stub shape kept; additions are additive)

`game.audio` (AudioEngine): `init() resume() update(dt,game) attachRacer(r) detachRacer(r) play(name, opts) setVolumes() dispose()`.
* `play(name, {pos:{x,y,z}, vol, p (pitch x), n (chain idx), sev, size, perfect, dur, bus:'ui'|'world', important})` -> bool. Names: `Object.keys(SFX)` (`src/audio/sfx.js`).
  UI code may call `game.audio.play('uiConfirm',{bus:'ui'})` directly, but emitting `ui:*` events is enough.
* Extras: `duck(depth, holdSec)`, `stats()` -> `{state,muted,voices,ai,engine,racers,played,volumes}`, `ctx`, `muted`, `musicIn`/`musicBus` (graph nodes), `played`/`log` (what was triggered; used by tests).
* `?mute=1` (any value except `0`/`false`): `muted`, **no AudioContext, no listeners**, every method a no-op. The context is created lazily on the first user gesture (`navigator.userActivation` or `resume()`), so there is no autoplay warning.
* Suspend/pause: tab hidden -> `ctx.suspend()`, visible -> resume. **Pause** (`game:pause`) does NOT suspend at once (the pause menu still needs UI sounds): world bus -> 0, music low-passed to 650 Hz and ~-5 dB; the context is suspended after 45 s paused and resumed on `game:resume`.

`game.music` (MusicPlayer): `init() resume() play(id,{fade,intro:false}) stop(fadeSec) stinger('win'|'lose'|'finalLap') update(dt,game) dispose()`, props `current`, `phase`, `targets`, `hasStingers`, `errors`.
* Self-driving: it listens to `game:state` (title/menu -> `menu`, results -> `results`), `game:raceStart` (course id; demo -> `menu`), `race:go`, `race:finalLap`, `race:finish` (stinger win/lose by place<=3). UI normally needs **no music calls**.
* Layers per race state (pure, unit-tested `layerTargets`): grid = base only (0.85); GO fades in `lead`; `drive` rises when chasing (low place), boosting, or under missile warning; `final` on the final lap; `lead` dips while tumbling; finish/results/menu = full stack.
* Failure of any file degrades silently (`music.errors` records it). Only the current track stays decoded (~75 MB for a 60 s 4-stem track: base+lead stereo, drive+final mono).

## Known issues / honesty

* **Not auditioned by ears.** Levels, balance and musical taste are set by numbers and heuristics: please listen via `tests/lab/audio.html` (SFX buttons + hotkeys, track play with per-stem toggles, engine sliders per craft, AI fly-by for Doppler, escalating warning, lock-on, gate chain). Tell me what to change; the composers/recipes are one-file edits. The `drive` stem of `sunrise` needed +16 dB of auto-trim (the marimba/tremolo-guitar program renders very quietly): if it sounds thin, raise those parts' `vol` in `tracks/sunrise.mjs`.
* `--solo` renders of the synth are not sample-additive (checked), so the balance uses raw peaks (exact) with an energy-NNLS cross-check; per-instrument balance *inside* a stem is by MIDI velocity/volume only.
* Opus at 32-52 kbps: drive/final are mono. Memory per decoded 4-stem track ~75 MB (only the current track is kept).
* Doppler is manual (WebAudio panner has none) and clamped 0.78..1.3. Camera cuts (> 450 m/s apparent) zero the listener velocity.
* The cannon spam from 7 AI is capped (6 concurrent, 50 ms gap) - it is audible only near the camera.
* `race:finish` plays a procedural jingle only if the stinger files failed to load.
* shader warnings in the console (`THREE.WebGLProgram ... X4122`) are not from audio.
