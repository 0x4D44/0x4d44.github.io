# Pass 9 — `harbour-hustle-cruise-cup/` (deliberate scoped review)

First pass of 2026-07-14. Area picked from the ledger: **`harbour-hustle-cruise-cup/`**
— a single-file arcade harbour-racing game: **`game.js` 1970 lines** (engine + UI +
storage + render all in one), `styles.css` 860, `index.html`. **No tests, no module
split, no service worker.** This was the higher-yield candidate (large untested
monolith) — but it turns out to be well-defended.

**Headline: clean bill — 0 bugs. A large untested monolith that is nonetheless
carefully written.** The lack of tests did not mean a lack of care.

**Verification I ran:**
- **Storage is guarded**: `storageAvailable()` (game.js:498) probes with a real
  set/remove in try/catch; `loadSave` (509) is try/catch-wrapped; and `migrateSave`
  (523) **sanitises every field** — captain sliced to 18 chars, coins/trophies/rep
  coerced to non-negative numbers, `unlocked`/`equipped` filtered to real parts,
  `highScores` coerced to an array. Robust.
- **The shared-save-code import is safe** (game.js:668-680): the pasted base64 is
  `atob`→`JSON.parse`d inside a try/catch (bad code → `alert`, no crash), then run
  through the same `migrateSave` sanitiser before use. A malicious shared code can't
  crash the game or smuggle unsanitised state.
- **No XSS**, even though captain name and shared save codes are genuine user input:
  the captain/raceName reach `innerHTML` only via the leaderboard, which escapes them
  with `escapeHtml` (game.js:895-896). Every other `innerHTML` sink (stat cards,
  part cards, HUD, result card, reward line) interpolates only authored `PARTS`/`RACES`
  data, emoji and numbers. The captain input's `.value` is set as a DOM property
  (game.js:755), not parsed as HTML.
- **No rAF leak**: the race loop's handle is cancelled by `stopRaceLoop`
  (game.js:1243-1244) on both quit (685) and finish (1833).
- **Economy has no integrity hole**: parts are unlocked by *winning* (guarded against
  duplicates, game.js:1888-1889), not bought with coins; coins are a pure loot counter.
  `highScores` is capped at 20 on the normal path (game.js:1913).

### Report-only (very-low — not filed)
- **`persist()` writes `localStorage` without a try/catch** (game.js:553). It checks
  `storageAvailable()` first, but that probe writes only a tiny test value, so a real
  save could still throw `QuotaExceededError` after the probe passes — and the almanac
  origin is *shared* across all documents' saves, so the origin-wide quota is a (remote)
  possibility. The sibling apps (cruise-line, shipshape) wrap `setItem`. Trivial fix:
  `try { localStorage.setItem(...); } catch {}`. Very low (a game save is ~KB; quota is
  MB), so noted, not filed.
- **Imported `highScores` isn't length-capped or per-entry sanitised** (game.js:530):
  `migrateSave` takes the imported array as-is. It's harmless — entries are escaped at
  render and the next race-finish re-`slice(0,20)`s the array — but for consistency a
  `.slice(0,20)` on import would match the normal path. Very low; self-correcting.

(`{{ }}` bindings, inline styles, a `<script type="text/x-dc">` game-logic block
authored in the design tool). There is no hand-written engine to fuzz. So this was a
**proportionate** review targeting the documented DC-export bug classes, not a deep
logic pass.

**Verdict: 0 bugs. The DC-export bug classes are largely clear here.**

# Pass 11 — `spectrum-analyzer/` (deliberate scoped review)

Third pass of 2026-07-14. Area: **`spectrum-analyzer/`** — a hand-built React
FFT/DSP *explainer* (`app.jsx` 1019 + `fft-section.jsx` 1039 + `index.html` 924),
React `.jsx` transpiled in-browser. Despite the name it is **not** a live-microphone
analyzer: there is no `getUserMedia`/`AudioContext` — it teaches the FFT with synthetic
signals and animated visualisations.

**Verdict: clean bill — 0 bugs. The load-bearing correctness surface (the FFT) is
verified correct against a reference.**

**Verification I ran:**
- **The radix-2 FFT is definitively correct.** `fft(re, im)` (fft-section.jsx:9-37) is a
  textbook in-place radix-2 (bit-reversal + butterfly with incremental twiddle). I
  differential-tested it against a naive O(N²) DFT over N = 2…1024, 200 random complex
  trials: **max |FFT − DFT| = 2.7e-11** (floating-point noise). It teaches a correct FFT.
- **No XSS**, despite two `dangerouslySetInnerHTML`. Both are fed only **hardcoded,
  authored** syntax-highlighted code snippets: app.jsx:863 `BugCode({html})` is called
  solely with the `BUG_CODE.b1..b4` constants (app.jsx:885/898/912/925), and
  fft-section.jsx:484 is an inline literal with **no `${}` interpolation**. Neither ever
  receives dynamic or user input.
- **No Web Audio lifecycle risk**: no mic/AudioContext; the single `requestAnimationFrame`
  (app.jsx:82) is cancelled in the effect cleanup (app.jsx:85), with the resize listener
  removed too.
- **No `localStorage`, no service worker** → none of those recurring classes apply.
- **Responsive**: `viewport` meta + many `@media` queries in the shell.

### Report-only (hardening note — not filed; upstream)
- Same **unpkg runtime dependency** as the other almanac React docs: `index.html` loads

# Pass 12 — `humanity-retention/` (deliberate scoped review)

Fourth pass of 2026-07-14. Area: **`humanity-retention/`** — a seed-driven
crisis-management strategy game (a fictional "retain humanity" dashboard: 5 global
meters + per-region infection/cooperation/economy, turn-based actions, events, endings).
Slice: `engine.js` 264, `app.js` 262, `content.js` 150 (data), `storage.js` 42,
`sw.js` 44, `audio.js` 67, + engine/static tests.

**Verdict: clean bill — 0 bugs.** Another well-built small app; infrastructure is a
model of the good patterns.

**Verification I ran:**
- Suite passes; extended into a **9000-run fuzz** (3000 each of tutorial/standard/crisis)
  playing random affordable actions + `advanceTurn` each turn, asserting all 5 meters and
  every region field stay in `[0,100]` after every action and every turn, the log never
  exceeds 18 entries, and every run terminates with a valid ending. **9000/9000 clean**;
  all ending types reachable (retained/managed/empty-shelves/overwhelmed). No crash, no
  invariant violation, no non-finite value.
- **Storage guarded + validated** (`storage.js`): all `localStorage` in try/catch (load
  catches, `saveProgress` catches quota, reset guarded); `loadProgress` runs the save
  through `importSave` → `migrateSave` (which sanitises achievements/codexRead to
  de-duped arrays and merges settings) before trusting it.
- **`sw.js` is the good pattern**: namespaced (deletes only its `humanity-retention-`
  prefix), caches **only** OK responses (`if (response.ok)`), and gates the app-shell
  fallback to navigations (`request.mode === "navigate"`). Matches the cruise-line
  reference.
- **XSS closed**: the only free-text input is the run **seed** (`app.js:26`), and it is
  rendered exactly once — `seed ${esc(run.seed)}` (`app.js:129`) — in a text context.
  `lastRun.seed` is stored but never rendered. `importSave` validates the pasted save.

### Report-only (very-low nit — not filed)
- `esc()` (`app.js:15`) escapes `& < > "` but not `'` (same shape as darmok's). Currently
  harmless — the only user string reaches a *text* node, not a single-quoted attribute —
  but adding `'` (and switching to a shared escaper) would harden it against a future
  attribute sink. Very low; noted.
