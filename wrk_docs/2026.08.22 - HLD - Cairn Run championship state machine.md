# Cairn Run championship state machine

The championship is one JSON-safe snapshot. Pure functions create and transition it;
standings and points are derived from immutable event results. The module imports no DOM,
renderer, audio, storage, or wall-clock API.

## State and cycle

The snapshot stores the championship/car/difficulty IDs, int32 seed, content version,
phase, event index, attempt number, live run ID, five-component carry-over damage, tuning,
and one result per completed event. Content definitions remain outside the save.

The uniform cycle is:

`service(i) → ready(i) → driving(i) → service(i+1)`, with the last submit entering
`classified`. `abandoned` is terminal. Service precedes every event, including the first;
on a pristine first car it acts as tyre/setup selection.

The public module will expose:

- `createChampionship`, `validateChampionshipState`, and `availableActions`;
- `planService`, `autoServicePlan`, and `applyService`;
- `startStage`, `abortRun`, `submitResult`, `retire`, and `abandon`;
- `rivalOutcome`, `stageStandings`, `overallStandings`, and `projectedSplits`.

Transitions never mutate input. An idempotent no-op returns the same object. Illegal phases,
stale runs, invalid results, infeasible service, unknown content, and invalid state use named
error codes rather than silent repair.

## Invariants

- `results.length === eventIndex` in every phase.
- `runId` exists exactly when the phase is `driving` and includes championship seed,
  current event, and attempt.
- A result's event ID matches its event index; every stored ID resolves against the same
  content version.
- Damage has exactly engine, steering, suspension, brakes, and body values in `[0,1]`.
  A stage may add damage but never heal it.
- Finished results have positive millisecond-rounded time, ordered splits matching the
  stage split count, and a final split equal to time. A retirement has no finish time.
- Rival results are stored once with the event result. Standings, points, gaps, and final
  classification are never stored.

`startStage` increments the attempt and mints the only valid run ID. `submitResult` accepts
that live ID once. Re-submitting any already-recorded run ID returns the same state and
ignores new payload; an aborted or foreign ID throws `stale-run`. Retry is explicitly
`abortRun` then `startStage`, so it cannot reopen service or reroll rivals.

## Rivals

Rivals are visible benchmark times, not hidden simulated cars. Their only inputs are the
championship/rival seeds, event index, authored stage duration band and surface mix, weather,
difficulty, rival skill/consistency/surface bias/damage risk, and a measured per-car benchmark
scale. They never read player time, attempts, assists, tuning, live damage, or a clock.

Skill selects a point between the authored fast/slow band. Bounded multipliers cover grip,
visibility, time of day, car pace, surface bias, and seeded consistency noise. A separately
salted bounded roll produces deterministic retirements. Retrying the event therefore cannot
change any rival outcome. Difficulty changes rival pace only; it never changes physics or
player timing. The HUD may show the precomputed target before the start.

Authored duration bands must have `slow / fast >= 1.15` and contain the measured reference
driver time. Car benchmark scales must remain in `[0.8,1.3]`. Formula golden values,
monotonicity sweeps, bounded random batches, and retry equivalence are required tests.

## Service

Each event declares the minutes available before it. A plan allocates non-negative minutes
to damaged components and may select tyre/tuning. Repair is linear and capped by existing
damage: engine 40 minutes/unit, suspension 25, steering 20, brakes 15, body 10. The planner
returns budget, used/remaining minutes, before/after values, cost, wasted minutes, and named
errors. Over-budget, negative, unknown, or invalid plans are rejected without changing state.

Automatic service is deterministic. It ranks weighted damage, spends no more than each
component can use, never wastes minutes, and spends exactly the lesser of budget and total
repair need. Championship rules do not grant a hidden free safety repair; vehicle damage
effects must remain drivable at their declared bounds.

## Persistence and recovery

The versioned save stores the whole snapshot under one key. On load, both save and
championship validators must pass. A partial/invalid championship is discarded while valid
profile and best-time data survive. A loaded `driving` state becomes `ready` through
`abortRun`, is persisted best-effort, and tells the player the stage will restart; mid-stage
physics is not saved.

The shell updates state before rendering the new screen and attempts one snapshot write at
every transition. Storage failure warns and continues in memory; it does not prevent driving.
The next successful snapshot resynchronises the whole championship. Exactly-once behavior in
the live session comes from `runId`, not from storage availability.

## Proof obligations

- Random legal action sequences preserve all invariants and JSON round trips.
- Frozen input proves transitions are pure; legal no-ops preserve object identity.
- Double submits, altered duplicate payloads, aborted-attempt results, retries, and abandons
  exercise exactly-once behavior.
- Every serialised prefix followed by the remaining actions reaches the same final snapshot
  as an uninterrupted run.
- A deletion/type/content-reorder mutation sweep makes validation fail for every structural
  invariant.
- Rival seed stability, monotonicity, bounds, skill dominance, independent DNF salt, and
  player-time independence are tested.
- Service results match the direct linear formula; automatic service is feasible,
  deterministic, non-wasting, and budget-exact.
- Stage standings sort finishers by time plus penalty before retirements. Overall standings
  derive points with deterministic tie-breaks and conserve the declared points table.
- A 1,000-seed six-event batch reaches classification without NaN, duplicate results,
  unbounded damage, or difficulty inversion.

## Tripwires

Stop and revisit this design before adding multi-leg events, mid-event service, retry limits
or penalties, rivals that react to the player or carry invisible state, multi-key persistence,
mid-stage saves, or a second championship with a different rival roster. Also stop if authored
duration bands do not contain measured reference times, full declared damage makes a pairing
impossible, or the seed mixer changes. `StageRun` split objects must be converted to numeric
times once at the game boundary.
