## flight.js
Exports as frozen in contract 5.2, plus `rollRel(fs)`. New state fields: `t, phi (full roll angle, + right wing down, +-PI inverted), kick, ctl{}, stunt{}`.

* Roll input = BANK ANGLE command (stick x 80 deg cap, rate limited). Released: `standard` assist levels wings (fades while pitch is held), `pro` holds the bank. In `pro`, holding roll = +-1 for > 0.3 s keeps rolling (manual roll, `roll` stunt); `standard` cannot roll past 80 deg by stick (barrel roll / loops instead). Consumers: command |roll| < 1 for sustained turns (pilotSteer already does).
* Bank-to-turn: nose rotates about WORLD up at `turnRate * lift-lateral * (cruise/speed)^0.8`. Pitch rotates about the aircraft's own right axis: wings level = loop, 90 deg bank = knife-edge turn. Yaw input = small rudder, +1 = nose right.
* Energy: thrust PD to cruise (capped), gravity 16 m/s^2 along the path (steep climbs x1.6, dives x1.3), induced drag when pulling/turning, airbrake 28 m/s^2 (never below minSpeed). `ctx.speedMul` scales target speed/thrust only, never rotation.
* Stall below 0.85 x minSpeed (exit at minSpeed): nose drops, authority 0.3, events `stall`/`recover`. A sustained vertical climb stalls (no hovering).
* Barrel: 0.65 s exact 360 deg, 12 m lateral shift, cooldown 1.15 s from start, `barrel.t>0` = evasion window, bank-turn suspended during it. `stepFlight` zeroes `c.barrel` (consumed).
* Tumble (`applyTumble`): speed x0.78 at once, spin 8.5 rad/s fading in the last 0.5 s, speed decays toward 0.62 minSpeed, then forced levelling.
* `applyImpulse(fs, v)`: forward part changes speed, the rest becomes a decaying lateral kick (`fs.kick`, 2.5/s decay, 40 m/s cap).
* Stunts to `fs.events` (capped 48): loop (330 deg pitch with wings roughly level, +25, 1 s debounce), roll (330 deg manual, +12), barrel (+6), inverted (up.y < -0.6 and |nose| < 37 deg for 1.2 s, then every 0.6 s, +4: a normal loop does NOT trigger it).
* Robust: sub-steps if dt > 0.02, dt clamped 0.1, NaN/Inf controls sanitised, deterministic, allocation-free per step.

Tuning: `FLIGHT` constants (export) and `flightParams(spec)`: cruise `70+6*speed` (94..124 m/s), minSpeed 0.55x, pitchRate `1.45+0.1*handling`, rollRate `2+0.2*handling`, turnRate `0.55+0.085*handling` (rad/s at 90 deg bank), levelRate `1+0.22*stability`, boostMul `1.38+0.02*boost`, accel `22+3*accel`, thrust `0.4*accel`.

Measured (falcon, lab telemetry): cruise 112 m/s (403 km/h); 80 deg bank holds altitude exactly, ~1.1 rad/s heading rate (about 100 m radius); loop 2.8 s, ~46 m radius, speed 110 -> 95 -> 109 m/s, ends at start altitude; boost 96 -> 164 m/s in 2.4 s (1.46x cap), FOV 72 -> 91; barrel 0.65 s / 12.0 m; vertical climb stalls. Handling order verified: sprite out-turns/rolls bulldog, wasp out-loops bulldog, manta > falcon > sprite top speed, comet accelerates harder than bulldog.

## pilot.js
`pilotSteer(fs, target, out, {aggressiveness=1, maxBank})` -> angular error (rad); writes pitch/roll/yaw only (boost, airbrake, barrel stay the AI's call). WORLD regime for targets ahead (heading error -> bank, elevation error -> pitch); PULL regime for above/behind/inverted/vertical (pitch + rudder for small errors, roll-onto-target + pull or roll-under + push with hysteresis for large). Tested: < 25 m RMS on a wobbling 3-D closed spline for all 6 craft; flies a 200 m-radius vertical loop (< 45 m error, inverted over the top); turns round to targets behind/above. `pilotLevel(fs, out)` recovers from inverted. `pilotAvoid(fs, target, [{pos,radius}], outTarget, {lookAhead, margin})` bends a target around spherical hazards; returns true if bent.

## camera.js
`createCameraRig(game)` -> `{mode, camMode, target, fov, init, reset(racer, mode), setMode, cycle, shake(a), update(dt, game, alpha)}`. Modes `chase` (14.5 back / 4.2 up at 11 m wingspan, scaled by wingspan 0.8..1.4), `far`, `low`, `nose`; `cinematic` (title: orbit / flyby / trail / side / front cuts on the race leader, deterministic list); `grid`; `finish`.
* The rig subscribes to `input:camera` in `init()` (cycles while `game.state==='race'`).
* AUTOMATIC: `reset(player,'chase')` + `race.state` `grid`/`countdown` plays the grid orbit, swoops behind the plane for 1.25 s at GO, and when `racer.finished` for the player it goes to the `finish` orbit after 1.2 s. `rig.camMode` is the effective mode. To skip the intro (tests) set `game.camOverrideNoIntro = true`.
* Reads only `racer.render.pos/quat` for placement; also `racer.flight.boost.active`, `controls.lookBack`, `finished`, `spec.visual`. Frame-rate independent damping (tested at 30/60/144 Hz). Bank follow 40 %, look-ahead into turns, FOV 72 -> ~95 with speed/boost, high-speed + hit shake (`rig.shake(0..1)`, scaled by `settings.shake`, halved by `reduceFlash`), ground clamp via `course.groundHeight` + 4 m, big jumps (> 250 m) cut instead of smear.
* Request to R/UI: call `game.cameraRig.shake(severity)` on `racer:hit` for the player (not wired by me; it needs `game.cameraRig`).

### Why 'assist' lost to 'hands' (decomposition)

Bot: `assist` = the guide flies, no roll / pitch keys, boost / fire / item / barrel / airbrake taken from the AI brain. Sunrise + Neon x seeds 7,1,3,5 (8 races each), Normal, falcon, `keybot-node.mjs --modes assist --off <class>`:

| Variant | Mean race s | Mean place |
|---|---|---|
| assist, everything on (old definition) | 233.4 | 4.9 |
| no boost | 232.9 | 5.3 |
| **no airbrake (X)** | **206.1** | **1.6** |
| no barrel | 233.5 | 4.5 |
| no fire + item | 233.6 | 4.8 |
| no airbrake, no boost | 212.8 | 2.1 |
| boost only (no airbrake / barrel / fire / item) | 205.1 | 3.0 |
| hands (no buttons at all) | 217.4 | 2.1 |

- The airbrake costs **27 s per race** (233.4 -> 206.1). The brain brakes for corners the guide flies anyway. Barrel and fire / item cost nothing in time (233.5 and 233.6 vs 233.4); fire / item only change places (they hit rivals).
- **Boost is worth 6.7 s per race** (212.8 -> 206.1, airbrake off both times), about 3 %. With the airbrake on, boost is worth nothing (233.4 vs 232.9): the brake cancels the gain. Boost itself is not a defect; it is a small gain. Whether 3 % is enough is a tuning call for the flight / race owners.
- Assist without the airbrake beats hands by 11 s (206.1 vs 217.4).
- Decision: `assist` no longer presses X (`CFG.assist.brake = false` in `skyblitz/tests/tools/keybot-node.mjs`). Reason: a person on Standard assist does not predict corners the way the brain does; X on top of the guide is a mistake, not skill. `tap` and `track` keep X: they model a player who steers the corners themselves with the brain's brake timing, and the airbrake also tightens the turn (E-19). Their cost was not measured separately; if tap / track places look low, try `--off brake` there. 8 races per cell is noisy.
- Game side finding for the flight owner: the brain's airbrake choice is poor for a guided craft. Nothing in the game punishes X beyond lost speed, so a player who rides X loses 27 s. No change made.
