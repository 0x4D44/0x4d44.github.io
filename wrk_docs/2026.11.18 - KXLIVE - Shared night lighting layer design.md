## 1. The answer

Build one **light-source registry** (pure data in `core/`). Derive every night effect from it:

- **Ground pools and light on facades**: compute them in the receiving surface's own shader. Every *scanned Lambert* receiver already passes through `addRoofShade` (`web/src/lighting.ts:452-499`; KX fog clones inherit it, Phong receivers do not, `atmosphere.ts:482-488`, `kx-night-fog.ts:78-79`), so that is the hook; Phong receivers need their own hook. It reads a world-space tile grid and a light texture. The instanced pool decals go.
- **Wet reflections**: keep one instanced quad per lamp as a screen bound. Replace its tuned streak constants with one shared wet-specular function of the same light record.
- **Fog**: each lamp's sprite evaluates an analytic single-scatter integral along the view ray. A coarse "city light density" texture, built from the same registry, sets how much the fog and low cloud glow.
- **Windows**: they stay a separate emissive system. They use the same photometric unit and the same exposure.
- **One scale**: lamp output in physical units (lumens, then candela), converted to scene-linear light by one constant. All lamp light goes through the scene's existing tone map. Today the pools, halos and reflections skip the tone map entirely.

Migration runs in nine steps. Each step sits behind a per-scene flag and is scored by the existing paired-capture loop. Day and Perth controls stay byte-exact. Old code is deleted one round after its replacement lands.

The ceiling has a catch the layer cannot fix. **N8 at night, and Perth N1-N5 and N8, are capped at 7.0** because no reference photograph exists (rubric "Gaps", `night-weather.md`). "Every criterion above 9.0" needs references sourced, or a rubric ruling, whatever we build. See decision D1.

## 2. Goal and non-goals

**Goal.** Each light source is described once. Its pool, its wet reflection, its fog halo and the light it throws on nearby walls all follow from that description and the weather state. This removes the per-station, per-weather hand tuning.

**Non-goals.**
- Daylight look (rubric E1-E6). Day frames must stay byte-exact.
- Train headlamps. `web/src/train-headlamp-light.ts` already does this right for 8 dynamic slots. It joins the layer at the end, or never.
- Signals, clock dials (`web/src/night.ts:161-193`), the sky dome's own model, rain and snow particles.
- Shadows from lamps (decision D5).
- New geometry or new lamp positions. The registry adopts today's positions.

### 3.2 Where the paths disagree

1. **Two brightness scales.** Lit walls and ground go through ACES at night exposure 2.3. Pools, halos and reflections are display colours added after it. A change of exposure (dusk 0.78 lamp level, or cloud) moves one and not the other. So the N5 dusk balance and the N6 rain balance cannot be right at the same time without per-state tuning. [fact for the mechanism; inference for the effect]
2. **The same lamp's energies are only loosely tied.** A sodium pool defaults to `0xffbc74 × 0.13`, but `poolCeiling` replaces the 0.13 where set (`streetlights.ts:31,464`). Reflections copy each pool's instance colour and multiply it by 2.5 or 3.625 (`streetlight-weather.ts:296`). The halo is `0xffa84a` at `0.9 × level` opacity (`streetlights.ts:480`). Fog spread scales sprite *size* by 9-20, not radiance (`streetlight-weather.ts:344`). So the pool and reflection are linked, but the halo's energy is set independently, and no part is in physical units. [fact; corrected after cross-family review]
3. **Two head systems for the same KX sites** (`atmosphere.ts:418-424`; the old one is removed at runtime when the new one exists, so nothing is drawn twice). [fact]
4. **Extinction differs by path.** Surfaces use `scene.fog` near/far (overridden for KX). Lamp sprites use their own 0.0045 and 0.0055 constants. The source fade uses `exp(-1.8 ...)`. So far lamps and far facades fade at different rates. N8 band 7 is "far lamps as bright as near ones". [fact]
5. **Scene geometry is hard-coded in shaders**: the WV frontage box (`streetlight-weather.ts:486-488`), the Princes Street box (`waverley-lamps.ts:203`), the Market Street x/z rules (`waverley-lamps.ts:211`), the Balmoral height bands. Any geometry move silently breaks them. [fact]
6. **Pools as decals.** They need floor masks and lifts (`poolLiftAt` 0.004/0.07), segment counts to drape on folded paving (`poolSegments: 12` per axis, 288 triangles per drawn pool, `city.ts:203`, `streetlights.ts:313-314`; r9's +172,480 was that round's increment, not the total), and they cannot light a kerb or a wall. [fact]

## 4. Data model

```ts
// core/light-sources.ts (pure, no three.js)
export type Spectrum = 'lps' | 'hps' | 'led-2700' | 'led-3000' | 'led-4000' | 'led-5000' | 'tungsten';
export type Optic =
  | { kind: 'road'; throwM: number; spreadM: number; cutoffDeg: number }   // asymmetric street optic (BS 5489 type II/III), aimed by yaw
  | { kind: 'downlight'; halfAngleDeg: number; softDeg: number }           // pendant, lantern, canopy
  | { kind: 'strip'; lengthM: number; widthM: number; cutoffDeg: number }  // KX masts' LED strips, platform line lights
  | { kind: 'flood'; aim: [number, number, number]; halfAngleDeg: number } // facade uplights (later, D6)
  | { kind: 'panel'; normal: [number, number, number]; w: number; h: number }; // lit glazing for reflections only
export interface LightSource {
  id: string;                 // stable: `${station}/${set}/${index}`
  station: 'kx' | 'wv' | 'pt';
  pos: [number, number, number];  // luminous centre (head), world metres
  footY: number;              // the receiving ground under it (pools, fog falloff by height)
  yaw: number;
  spectrum: Spectrum;
  lumens: number;             // total output; candela follows from the optic
  optic: Optic;
  cover: 'open' | 'under-roof'; // what it may light (with cover.ts)
  tags: readonly string[];    // 'road', 'platform', 'approach', 'euston-road', 'mast', 'open-platform', ...
  fog?: number;               // multiplier on scattering for exceptional glass; default 1
}
```

## 5. Rendering from one record

### 5.1 Constraints [fact unless marked]

- three `^0.187.0` (`package.json`), WebGL2, GLSL ES 3.00, so `texelFetch` and float textures are core. Tone mapping is per material. There is no post chain: the only render target in `web/src` is the shadow map (`lighting.ts`).
- Uniforms: WebGL2 guarantees only 224 fragment uniform vectors. 900-1300 lamps cannot be uniform arrays. The 8-slot headlamp array (`train-headlamp-light.ts:24`) works because it is small.
- Texture units: 16 guaranteed per fragment stage. Lambert programs already sample map, shadow map and cover map, and some sample the lamp-surface, platform or open-platform maps. Two more (light data and tile grid) fit. [inference]
- Budgets: 2M triangles and 1000 draws. Night shots today: KX 278-557 draws, 1.04-1.20M triangles; WV 368-543 draws, 1.67-2.15M triangles (p5w and Calton over 2M, ALM-BUG-FLU-00023); PT 69-84 draws (r15 `head/manifest.json`).
- Lights in reach of one point. Road spacing is 18 m, alternating sides (`core/streetlights.ts` `LAMP_RULES`). An influence radius of about 25 m reaches 4-8 lamps on a main road. A platform with 8-10 m pools reaches 6-12. [guess] Cap at 16 per tile on desktop and 8 on mobile.

### 5.2 Ground pools and facade light: analytic in the receiver (recommended)

Two textures are built once per scene from the registry:
- `uLightData` (RGBA32F, 4 texels per light): position and lumens; linear colour and optic kind; aim, cutoff and throw; cover and fog flags.
- `uLightGrid` (R16UI or RGBA16UI): a world XZ grid of 8 m cells over the scene's extent. Each cell holds an offset into an index list of the lights whose influence sphere touches it. Lights are static, so there is no per-frame update.

GLSL `vec3 nightLightAt(vec3 p, vec3 n)` loops over the cell's lights (`break` at the cap). Per light: inverse-square illuminance × the optic's intensity at that angle × `max(dot(n, l), 0)` × a smooth range window × a cover gate (`coverOpen` from `cover.ts`, so a street lamp does not light the shed floor and a pendant does not light the street). It is added in `addRoofShade` beside `HEADLAMP_LAMBERT`, gated by `uNightLights > 0`. By day the loop never runs and the program output is unchanged. This is exactly how `uHeadlampCount` keeps the day frames identical (`lighting.ts:446-450`).

What it fixes: pools take the real paving, kerbs, steps and slopes; LED and sodium pools differ by optic and spectrum; overlaps add physically; walls, kerbs and bridge parapets near a lamp catch light, which is the N3 "lower-storey wash". Floor masks, lifts, pool segments and the open-platform bake (`station-lamps.ts:24-91`) become dead code. Triangle and draw cost: **minus** the pool InstancedMeshes: one draw per layer and up to 288 triangles per drawn KX pool (12×12 segments). The saving must be computed from the actual instance counts per view in S0's probe; the earlier "about 170k" figure was r9's increment, not a measured total [corrected after review]. This also helps ALM-BUG-FLU-00023 at WV.

Fragment cost [guess]: 1280×800 with about 2× overdraw is about 2M fragments. Times 6 lights at about 40 ALU is about 0.5 GFLOP per frame. Fine on desktop. On mobile, cap at 8 and use a coarser grid.

**Alternatives considered**
- *three.js PointLight / SpotLight*: every light enters every program, and 1000 of them do not compile. Rejected.
- *Baked irradiance texture* (as `lightOpenPlatformPaving` does): cheap, but ground only. It has no normal response for walls, needs about 0.5 m cells to hold hard LED edges (a 2 km extent would need 4000² texels), and is wrong on bridges and decks. Keep it only as the far-field fallback for the panoramas (decision D7).
- *Instanced decals with a shared profile*: what we have, minus the flags. It cannot light walls and keeps the "decal spots" look. Rejected as the end state, but it is the S1 parity baseline.
- *Deferred or clustered 3D shading*: needs a G-buffer pass three does not provide. Too big a framework change.

### 5.3 Wet reflection: one shared specular function

A wet ground point reflects a lamp that can be 100 m or more away (today's reach is 96-160 m, `station-lamps.ts:116`, `waverley-lamps.ts:211`). The tile lookup only holds lamps within about 25 m, so the reflection cannot live only in the receiver.

Recommended: keep one instanced quad per reflecting lamp as a screen-space bound, placed by today's mirror construction (`streetlight-weather.ts:146`). Replace its body with `lampWetSpecular(light, P, V, wet, rough)`: GGX with roughness from wetness and the surface (puddled asphalt 0.08-0.25 [assumption]) and the light's real intensity toward the mirror direction. Streak length and taper then come from roughness and viewing angle, which is how real streaks behave (R-nw-j). The constants at `:159-197`, the 2.5/3.625 gains (`:296`) and the KX/other blend split (`:110`) go. Near-field specular (within the tile radius) is added in the receiver at no extra cost, so a lamp's pool and its reflection under the head blend into one another.

KX lunettes, facade and window reflections (`kx-front-reflections.ts`) become `panel` sources in the same pass, so the Midland window streaks and lamp streaks share one function. This also fixes r9's "unlit-pane streaks darken the lit road": energy is only ever added.

Alternative: screen-space reflections of the lit frame. They need a scene colour copy (one more pass plus a target) and fail at frame edges. That is the r11 "orange sliver at the left edge" in another form. Not now.

### 5.4 Fog: analytic in-scattering per light, plus a city glow

Per light, the in-scattered radiance along a view ray through homogeneous fog with an isotropic phase has a closed form for a point source. With closest-approach distance h, ray offsets t0 and t1 and extinction σ, `L ≈ I·σ/(4π h) · [atan(t1/h) - atan(t0/h)]` times `exp(-σ · d_cam→light)` (the standard airlight approximation). [fact for the formula; assumption that the approximation holds at our densities] Evaluate it in each lamp's halo sprite, one Points draw per scene. Size the sprite on screen from σ and intensity: the radius at which the scatter falls below 1/255 after exposure. Then:
- halo width and fall-off follow visibility (rubric N8: "wider soft halos", "far ones fade") with no `fogHaloSpread`;
- σ is the same as the surfaces' fog, derived from the same `visibilityM`. That ends disagreement 4;
- the core stays bright because it is a separate term, the source seen through `exp(-σd)`. This answers r12b/12c ("cap only the scattered halo/glow, never the core") structurally;
- coincident fittings are deduplicated once in the registry, not per shader (`streetlight-weather.ts:323-332`).

**City glow.** Build a 64×64 "light density" texture over the scene: the sum of lumens per cell, blurred. The fog fragment samples it to brighten and warm the fog colour over lamp groups, using the lights' own chromaticity. The dome horizon takes the mean of the visible density. This replaces the per-scene `cityFogTint` constants and the weights in `atmosphere.ts:692-712`, gives the r12 "lift over lamp groups" for free, and carries over to rain cloud (`rainCloud`, `:705`).

Occlusion: a sprite is depth-tested at the lamp, so a lamp behind a wall loses its whole halo, while one in front keeps all of it, even over a roof. [fact, current behaviour] Clipping the integral by scene depth needs a depth texture (decision D4).

Stacking and clipping: with per-material tone mapping, additive sprites sum after the tone map, so 30 overlapping halos can clip (the r12 HOLD). Two cures. (a) Soft-saturate each sprite (`1 - exp(-x)`), which the r12b note asked for. That is cheap but per sprite, not per sum. (b) Render night frames into a half-float target and tone-map once (decision D2).

### 5.5 Facade floodlights and windows

- **Floodlights** (KX front, Midland, Balmoral) stay hand-shaped emissive for now (`lighting.ts:491`, `landmarks.ts:38-110`, `waverley-night.ts:84-112`). They score, and the N3 complaints are about shares and tints, not their model. Later they can become `flood` sources in the same list (decision D6).
- **Windows** stay the hashed emissive `WIN_NIGHT_GLSL`. Two changes: express pane radiance in the shared unit (section 6), so dusk and night exposure treat windows and lamps alike; and add each building's lit-window flux to the city-glow density (5.4), so a lit block warms the fog above it.

## 6. One photometric scale and exposure

Today: surfaces are physical-ish (sun 3.0, sky 1.0, `lighting.ts:3`) at an exposure of 2.3 at night, while the lamp layers are fitted display colours outside the tone map (`streetlights.ts:23-29`). Every round re-fits a luma target for a given state. [fact]

Proposed:
1. **Unit.** Scene-linear radiance: 1.0 = K cd/m². The sun rig already implies K. Fit it once so that a mid-grey wall at noon renders as today. [assumption]
2. **Lamp output.** Lumens → candela by optic → illuminance `E = I·cosθ / d²` → surface radiance `albedo·E/π`. Check against the photos: road under a 10 m sodium head about 20-30 lux, about 1.5-2 cd/m² on asphalt. [assumption, UK practice]
3. **Calibration (step S1).** Pick the one global lumens-to-unit factor so that the brightest pixel of an Euston Road pool at `night-clear` matches main (pixel probe). Every other lamp then follows from its lumens, with no per-lamp fit.
4. **Exposure.** Keep the fixed per-state exposures (`core/daylight.ts:236-238, 327`). No auto-exposure: it would move day controls and make captures order-dependent. Because lamp light now passes through the same tone map, dusk (`lampLevel` 0.78) and rain (exposure plus cloud) are consistent by construction.
5. **Lamp level.** One `lampLevel` scales source lumens. Today `lampLevel` and `headlampNight` differ by gloom (`atmosphere.ts:646-649`). Keep that split explicitly, as "lamps on" vs "photometric night", and document it.

## 7. Migration plan

## 8. Risks

1. **Accepted looks regress.** KX Euston Road pools, mast line pools and Balmoral streaks took 5-10 rounds each. A physical model may first score lower. Mitigation: flag per effect and scene, BASE = main, the D3 rule, and fitting optic parameters (not per-lamp gains) to the same photo values.
2. **Mobile fragment cost.** [guess] A 6-16 light loop on every Lambert fragment at night. Mitigation: per-device cap, coarser grid, `break` on the cap. Measure on the slowest supported device in S2.
3. **Light leaks without shadows.** A street lamp near a building lights the inside face of an arch or a recess. The headlamp light has the same caveat (`train-headlamp-light.ts:5`). Mitigation: N·L, the cover gate, per-light half-space planes for kerb-side lamps. See D5.
4. **Two-state render instability** (ALM-BUG-FLU-00024) makes "byte-exact controls" flaky on KX day frames. A real layer change and noise look the same. Mitigation: three runs of BASE per pack, as rounds 14-15 did.
5. **three upgrade.** A new three can move anchor text. The squeeze guard catches it at build time, not at runtime.
6. **Over-reach.** The registry tempts moving windows, floodlights and trains in too. Keep them out until S9 lands.
7. **Rubric caps.** N8 at night and Perth N1-N5 and N8 cannot pass 7.0 without references (D1). Without a ruling, the layer's N8 work cannot move the score past 7.

## 9. Decisions owed by Arthur

**D1. Rubric caps vs the goal "every criterion above 9.0".**
- Today: the rubric caps any criterion with no reference at 7.0. That is N8 at night everywhere, and Perth N1-N5 and N8 (`night-weather.md`, "Gaps"). N8 is 6.75 now against a 7.0 cap.
- Example: a flawless fog halo at Waverley still scores at most 7.0.
- Options:
  - (a) Source references, for instance a geograph or Flickr CC night-fog shot of any UK station or street and a Perth night shot. This costs a search pass and no code.
  - (b) Rule that physical plausibility may score above 7 for night fog.
  - (c) Accept 7.0 as the N8 ceiling.
- Pick: (a) now, with (b) as the fallback for night fog only. Without one of them the goal cannot be met.

**D2. Tone-map lamp light once (night-only half-float target), or stay per-material.**
- Today: halos and fog sprites are added after each material's tone map, so overlaps clip (r12: shed 25% clipped, WV p5w 57%) and caps then dim the cores (r12b).
- Options:
  - (a) Stay per-material. Pools, facades and near specular are inside the surface shader, so they are tone-mapped right. Only sprites and reflection quads use soft saturation. Zero framework change, but sprite stacking stays approximate.
  - (b) A half-float target plus a final tone map, only when `lampLevel > 0`. Day frames keep today's path, so they stay exact. This costs one full-screen pass and about 8 MB at 1280×800 (more at DPR 2), and it changes the rendering framework.
- Pick: (a) through S7, then (b) as S8 only if the clipping or stacking complaints remain.

**D3. Land a neutral step that deletes code?**
- Today: rounds land on score gains. A replacement step may score equal while deleting hundreds of lines and a dozen flags.
- Options: (a) land on "no value falls, look neutral, net code removed"; (b) require a gain.
- Pick: (a). Otherwise migration stalls on steps that are pure parity.

**D4. Depth texture for fog occlusion.**
- Today: a halo is all-or-nothing on the lamp's depth test, so it can glow over a roof in front of it.
- Options: (a) none; (b) let the main pass write a depth texture (three `DepthTexture` on a target, which implies D2 b) and clip the scatter integral by it.
- Pick: (a) now. Revisit with D2.

**D5. Shadows from lamps.**
- Today: none for any lamp. Train headlamps leak through walls within range by design.
- Options: (a) none, plus a cover gate and half-space planes; (b) a top-down occlusion height map per scene (one texture: light is blocked if a building height exceeds the ray height); (c) shadow maps for the nearest N lamps (heavy).
- Pick: (a), then (b) if S4 shows leaks the scorer marks.

**D6. Floodlights as sources.**
- Today: height-band emissive tuned to photos (KX front, Midland, Balmoral).
- Options: (a) keep; (b) convert to `flood` optics after S9.
- Pick: (a). The N3 gaps are window share and brick tone, not floodlight geometry.

**D7. Panoramas' far field.**
- Today: WV skips pools for lamps more than 250 m from the world origin, not from the camera (`waverley-lamps.ts:203`, `poolAt`), and Calton shows lamps as cores.
- Options: (a) the light field everywhere (the per-pixel cost is the same, and far tiles are small on screen); (b) a baked low-res irradiance for beyond 300 m.
- Pick: (a), measured at S5. Fall back to (b) if Calton's frame time rises.

**D8. Perth.**
- Today: Perth is an exact control in every pack and is unreferenced for most criteria.
- Options: (a) migrate Perth with S5; (b) keep it frozen as a control until S9, then migrate in its own round with day-only controls.
- Pick: (b). It keeps the loop's strongest control intact during the risky steps.

**D9. Parallel with incremental rounds.**
- Today: rounds edit the same three files the layer replaces.
- Options:
  - (a) Rounds continue anywhere, and each layer step rebases onto them. This risks re-fitting effects that are about to be deleted.
  - (b) Once a layer step starts on an effect and scene, rounds stop tuning it there and work on windows, sky, snow, floodlights and trains.
- Pick: (b). S0-S2 can start at once with no conflict.
