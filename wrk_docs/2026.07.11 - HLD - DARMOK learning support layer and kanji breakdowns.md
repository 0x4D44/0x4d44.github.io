# HLD — DARMOK learning support layer + kanji breakdowns

**Status:** in build · **Author:** Claude (Opus 4.8) · **Date:** 2026-07-11
**Repo:** `0x4d44.github.io`, document `darmok/`

## Why

Playtest feedback (Arthur's wife, first level): the course throws *recall* at you
after a single viewing (e.g. 艦長 "captain" appears once in the vocab list, then a
`type` exercise demands you produce 私は艦長です), gives no hints when you're stuck,
never notices you're struggling, has no getting-started orientation, and never
explains the kanji themselves (no radicals, no Japanese-vs-Chinese contrast).

Arthur's decisions: **build both the support layer and the kanji system as one drop;
rich kanji treatment across all 12 weeks; the in-game helper is Lt. Cmdr. Data.**

## Scope

Two coherent pieces, one release:

### A. "Data" learning-support layer (fixes the bounce)
1. **Gentler first exposure.** In `DK.buildSession`, first-time (non-review) lessons
   lead with *recognition* drills (`meaning`, `reverse`, `listen`, `match`) and defer
   *production* (`typeback`) — production belongs to Review shifts and the SRS drill,
   after the learner has met the word in recognition first. Review shifts keep the
   full mix.
2. **In-exercise hints (Data).** Every exercise gets an **ASK DATA** affordance giving
   *progressive* hints in Data's voice:
   - `mc`/`listen`: first hint eliminates two wrong options (50/50); second gives a nudge.
   - `type`: reveal the reading, then the first kana, then the meaning.
   - `build`: highlight the first token.
   Hints are **free** (matches the "no hearts, no guilt" ethos). Using a hint marks the
   item `_assisted` so it doesn't count as a clean first-try for the medal, but still
   advances SRS. Never blocks progress.
3. **Struggle detection (Data steps in).** Track consecutive wrong answers across the
   session (`S.streakWrong`) and per-item lapses (already in SRS). After 2 consecutive
   misses, Data proactively surfaces a comm panel with a targeted tip and offers the
   next hint. Calm, literal, encouraging — never punitive.
4. **Onboarding.** First run (no `settings.onboarded`), Data runs a short guided intro:
   what a Mission/Shift is, the brief→vocab→sim loop, "nothing is locked, rank is never
   lost," the rōmaji IME, and where help lives. Dismissible; re-openable from the bridge
   ("ORIENTATION" / a `?`).

### B. Kanji breakdowns (all 400 curriculum kanji)
- **Data model:** new registry `DK.KANJI` (object keyed by the kanji char), authored in
  `darmok/kanji.js` (loaded before `app.js`). Entry:
  `{ k, m (meaning), on:[katakana], kun:[hiragana w/ okurigana dots], rad:[{c,m}], mn (mnemonic), cn (JP-vs-Chinese note, "" when none) }`.
  Authored + adversarially accuracy-verified by workflow `darmok-kanji-authoring`
  (verify pass deletes any JP-vs-Chinese claim it cannot confirm — accuracy over coverage).
- **Tappable kanji.** Kanji in vocab cards (and optionally briefing examples) become
  tappable → open a **kanji breakdown modal**: big glyph, meaning, on/kun readings,
  radical components with glosses, mnemonic, and the JP-vs-Chinese note when present,
  plus a ▶ to hear the on/kun. Implemented by wrapping kanji in `DK.ruby` output with a
  `data-kanji` hook (only for chars present in `DK.KANJI`).
- **KANJI reference tab.** New tab in `viewReference` listing every curriculum kanji
  (grouped by week / searchable), each opening the same breakdown.

## Architecture / where it hooks

- `engine.js`: `DK.KANJI` lookup helpers (`DK.kanji(char)`, `DK.hasKanji`), the
  `buildSession` scaffolding change, and a `DK.rubyK` variant that tags known kanji.
- `app.js`: kanji modal + `data-kanji` handler; KANJI ref tab; `askData`/hint state on
  the exercise; struggle detector in `answer()`; onboarding overlay; Data comm-panel
  renderer. New `data-act`s: `hint`, `ask-data`, `close-modal`, `onboard-next`,
  `onboard-skip`, `open-kanji`, `orientation`.
- `lcars.css`: modal, Data comm panel, hint styling, onboarding overlay — all reusing
  existing LCARS tokens; responsive (must hold 360/390px, 0 overflow).
- `index.html`: add `<script src="kanji.js">` before `app.js`; bump nothing else.

## Invariants / constraints

- **No network.** `kanji.js` is local data; no new CDN calls.
- **Storage-safe.** New settings (`onboarded`) go through the existing guarded
  load/save; default off. Back-compat: old saves lack the field → treated as not
  onboarded (fine).
- **Mobile.** Everything holds at 360×640 and 390×844 with zero horizontal overflow
  (repo's recurring sin); modal scrolls internally.
- **Render model.** Modal/onboarding are overlays appended outside the `#app`
  full-render churn, or re-rendered idempotently, so they don't fight `render()`.
- **Accuracy.** Kanji content is verified; the SW is absent so no cache-bump needed,
  but returning visitors get the new `kanji.js` on next load.
