# 2026.06.27 - HLD - Quarto AI engine upgrade

Status: SIGNED-OFF (2026-06-27)

## Goal (one line)
Replace Quarto's ad-hoc one-ply AI with a single bounded **minimax** search,
giving a real easy→medium→hard ladder that's genuinely challenging — without
changing the engine's public API, its callers, or the UI.

## Context
- `quarto/quarto-engine.jsx` exposes pure logic on `window.QuartoEngine`, incl.
  `aiChoosePlacement(state, difficulty)` / `aiChooseGift(state, difficulty)`.
- Today medium & hard share one-ply logic (take immediate win; restrict to "safe"
  moves/gifts that don't let the opponent win next move; else random pick).
  `'hard' === 'medium'`. Verified this session: a 2-ply searcher beats it ~97%, never loses.
- Key engine fact: **`applyPlace` does NOT flip `current`** (only sets phase→select,
  and `winner = current` on a completing placement); **`applySelect` is the only
  transition that flips `current`.** So within one turn the same player places *then*
  selects; perspective flips only at select→place. (This breaks naïve "negate-every-edge"
  negamax — see Approach.)
- The AI runs **synchronously** inside index.html's "thinking" `setTimeout`, and
  `'hard'` also backs the **Hint** button → must be strong AND fast.

## Goal / Non-goals
**Goals**: `hard` = fork-aware search (avoids forced losses in its horizon, always
takes wins, presses forks), snappy (~<150 ms/move, keeps Hint instant), mostly draws
vs perfect play. `medium` = genuinely-better shallow search. `easy` = unchanged random.
`aiChoose*` signatures unchanged → zero caller/UI churn (Hint improves for free).
**Non-goals**: new levels; UI/settings changes; async/worker/MCTS; opening books;
"Online"; any non-AI feedback from the prior review.

## Approach
One bounded **minimax keyed on `state.current`** (NOT negamax) replaces the per-difficulty
heuristics:
- `evaluate(board, held, current, depth, …) → score` from a **fixed root player's**
  perspective: a node is a MAX node if `current === root` else MIN. This is correct for
  Quarto's non-alternating place→select structure (the same player's place and select are
  both MAX/MIN; perspective flips only when `current` flips at a gift).
- **Terminal from the win rule**: a completing placement → the placer (`current`) wins
  → `+1` if placer===root else `−1`; full board → `0` (draw). [2-ply walk verified in review.]
- **Lean make/unmake**: the search runs on a single `board[16]` + `held` + `current`,
  mutating and undoing in place; it never calls `applyPlace`/`applySelect` (which copy the
  whole `history` each call). Uses `findWin`/`placementWins`/`emptyCells`/`remainingPieces`.
- **Depth in plies** (each place OR select = 1 ply), chosen **once at the root**, adaptive
  by empty-count: shallow when many empties, deep enough to reach terminal when few. The
  opening is never searched deep (no blowup); forks resolve in the small endgame tree.
- **Leaf heuristic** at a non-terminal cutoff (only reached mid-game): with **one-ply
  quiescence** — if the side to move at the leaf has an immediate winning placement, return
  ±1 (root view) [R2]. Otherwise a **safe-reply differential** = (`#` pieces *root* could be
  safely handed) − (`#` pieces *opponent* could be safely handed), from the fixed root
  identity, **normalised strictly inside (−1,+1)** (e.g. `/64`, so |leaf| < 0.25) so it can
  never outrank a real ±1 terminal [R3]. Direction pinned: more safe outs for root ⇒ higher.
- **Unconditional floors** wrapping the search (never weaker than today) [R1/F2]:
  placement always takes an available immediate win, else is **restricted to the "safe"
  placement set** (today's lines 96–105) when one exists; gift never hands a piece the
  opponent can win with immediately if a safe piece exists. The search optimises **within**
  the safe set; under a budget cut-off, best-so-far is confined to that safe set.
- **Root selection**: evaluate each (already floors-filtered) candidate with a **full
  window** (no cross-sibling pruning) → exact per-move value → argmax with a **deterministic
  tie-break** (lowest cell / lowest piece id). Interior alpha-beta is fine. [F4]
- **Determinism**: the search is fully deterministic; **no `rng` param is added** to
  `aiChoose*`. Only `easy`'s randomness flows through a module-level swappable `randomFn`
  (default `Math.random`), exposed as a `_setRandom(fn)` test hook. [F5]
- **Difficulty → (maxDepth, node-budget)** on the same search: `easy` = random (today's,
  unchanged); `medium` = floors + shallow cap (~4 plies); `hard` = floors + adaptive deep
  (exact endgame) + a node budget kept ~<150 ms; if the budget trips, return best-so-far
  within the safe set. (Iterative deepening considered, rejected for simplicity — adaptive
  depth already avoids the opening blowup.)
- **Implementation watch** [R4]: scores can be `0`; always compare numerically, never via
  `x || …` / `!x` truthiness.

## Acceptance criteria
**Deterministic — committed golden-position harness** [F8]:
- A1. medium & hard take an available immediate winning placement.
- A2. medium & hard never hand a piece the opponent can win with immediately when a safe
  piece exists (gift safety floor).
- A3. medium & hard never *place* into an avoidable one-ply-loss when a safe placement
  exists (placement safety floor — the never-worse-than-today guarantee) [R1].
- A4. hard finds a forced win where one exists within the endgame horizon, and **avoids the
  specific 2-ply fork the old one-ply walks into** (regression position from this session) [R2].
- A5. Engine stays pure (no DOM/new globals); `aiChoose*` signatures unchanged; no new env
  vars/flags; choices deterministic under fixed `randomFn`.
**Recorded validation (journal, not committed — flaky as asserts)**:
- A6. hard's per-move compute ~<150 ms across a full self-play game.
- A7. A strong reference searcher wins ≈ 0 and mostly draws vs `hard` (vs ~97% vs old
  medium); `hard` beats `easy` ≥ ~95% over ≥ 40 games.

## Decision log
- **Minimax keyed on `current`** (not negate-every-edge negamax): the place→select edge
  doesn't flip `current`, so negamax would model the AI sabotaging its own gift. [F1]
- One search, difficulty = (depth, budget); keep `aiChoose*` API → no caller/UI churn.
- **Floors-first within a safe set** → provably never weaker than today, even under the
  budget cut-off. [R1]
- **Leaf = quiescent + bounded** safe-reply differential → midgame is sensible and the
  heuristic can't outrank a proven win; uniform root depth keeps leaf values comparable. [R2,R3]
- Deterministic search + `_setRandom` hook → testable without an API change. [F5]
- Golden-position committed tests; timing/strength recorded only → no flaky CI. [F8]
- In-browser harness with cache-buster (no node; SW caches scripts). [F7]
- Adaptive depth over iterative deepening — simpler, and it sidesteps the opening blowup.

## Review findings folded in (all survived refutation)
F1 negamax→minimax-on-`current`; F2/R1 keep placement-safety floor + safe-set best-so-far;
F3/R2 quiescent leaf; R3 bounded leaf; F4 full-window root; F5 no-rng-param + `_setRandom`;
F6 lean make/unmake; F7 cache-buster harness + v6 bump; F8 golden positions + recorded perf.
Refuted (not folded): infinite-loop risk (tree is acyclic — a cell/piece is consumed each
ply) and `held==null` select (never occurs in normal flow).

## Residual risks
- Heuristic midgame (between the opening and the exact endgame band) can still be out-played
  by perfect play setting a >horizon fork → acceptable per "solid & snappy"; the floors cap
  the downside at today's safety.
- Node-budget value is a tuned constant; if perf testing shows it trips often mid-game, the
  endgame band shrinks → revisit (would only ever degrade toward today's strength, never below).
- Harness is Chrome-driven, not headless CI → acceptable (repo has no build/test infra by design).
