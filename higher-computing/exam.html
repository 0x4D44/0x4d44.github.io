The parade ground · Exam technique

Exam drill

Knowing the content is half the battle. The other half is giving the examiner exactly what the marking instructions reward, in the time available.

1 · Timing the question paper

You have 120 minutes for 80 marks: one and a half minutes per mark. Use it as a budget:

PartMarksBudget
A quick look through the whole paper–≈ 3 min
Section 1: Software design and development, and Computer systems55≈ 80 min
Section 2 (Database) or Section 3 (Web): answer only one25≈ 35 min
Checking–≈ 2 min
⚠ Answer the right option

Answer Section 2 or Section 3, whichever option you studied. Don't split your time between both.

Each section opens with short, mostly "C"-grade questions in simple contexts, then moves on to longer, context-based questions that include "A" marks. The examiners advise: always attempt the large-tariff questions. They are built to contain C marks as well as the A-grade discriminators, so even a partial answer scores.

2 · Command words

The verb at the start of a question tells you how much to write. Extended "describe" and "explain" answers are still the area candidates find hardest (2025 course report).

WordWhat it wantsExample answer (1–2 marks)
State / identify / nameA short fact, with no reason needed.State the bus used to send the address. "The address bus."
DescribeSay what happens or what something is like, in enough detail. Typically one mark per relevant point.Describe a watchpoint. "A watchpoint is set on a variable. Execution pauses whenever that variable's value changes, so the programmer can inspect it."
ExplainSay why or how: give a reason or a consequence. Use "because…" or "so that…".Explain why more cache improves performance. "More instructions and data can be held in cache, so there are more cache hits. Fewer slower accesses to main memory are needed, so instructions are fetched faster."
CompareBoth items, on the same point, linked by a connective such as "whereas" or "but"."In agile, testing happens during every sprint, whereas in iterative development testing is a separate phase after implementation."
EvaluateJudge the solution against the named criterion, with evidence from the code, test or specification."The program is robust, because entering 'Q' for the flight is rejected and the user is asked to re-enter (test 5)."
Write / design / completeProduce code, SQL, a design or a diagram. Any language is accepted, and the marks are for the logic."Using a design technique, show the refinement of step 2…"
Refer to the context

The 2025 report: "Candidates should refer their answer to the context of the question and not just the operation of the lines of code." When asked what code does, say what it achieves in the scenario ("finds the cadet with the most flying hours"), not just "it loops and compares".

3 · The assignment

  • 6 hours, usually spread over several lessons, under supervision. It is open book: class notes, programming manuals, textbooks and your own programs are allowed.
  • Task 1 (Software, 25 marks) is compulsory. Then do Task 2 (Database) or Task 3 (Web), each 15 marks.
  • About 22–24 of the 40 marks are for implementation. The rest are for analysis, design, testing and evaluation, which candidates do worst on.
  • Follow the design you are given. If the brief supplies a data flow and refinements, your code must implement those, using the sub-programs and parameters exactly as shown.
  • Check the output against every requirement, not just "it ran". Make SQL work for all data (>= versus >), and match web pages to the wireframe exactly (margins, positions).
  • Evaluations must refer to your code: name the function, loop or data structure. Generic National 5-style answers get little credit.
  • Hand in only the pages with your evidence, in task order. Discard pages that only contain instructions.

5 · The examiners' greatest hits: common mistakes

Every item here comes from the 2025 course report.

  1. Generic evaluation answers ("it is efficient") that don't refer to the actual code.
  2. Answering about robustness when the question asked about fitness for purpose.
  3. Giving a digital certificate's benefit when asked about a digital signature.
  4. Recognising a vector image without using technical terms (objects, attributes, resolution independent).
  5. Adding unnecessary parameters to a data flow.
  6. Writing two near-identical sub-programs instead of one with a parameter, called twice.
  7. Describing the code to change when the question asked what code to add.
  8. SQL: vague error answers ("missing join") instead of the exact fix; missing GROUP BY; not combining SUM with a calculation; > where "at least" needed >=.
  9. Not explaining that a new entity is needed to resolve a many-to-many relationship.
  10. Web: not spotting float as the cause of a layout fault, or missing clear:both; margins that exceed the container width; confusing block and inline placement; answering "screen size" when the issue is resolution.
  11. Web functional requirements that don't mention form elements or JavaScript events.

6 · Mock broadside: exam-style questions

Longer questions in the exam's style, each with marking guidance. Write a full answer before you reveal the guidance, then give yourself the marks you earned against each marking point. The first set is a complete context-based question of the kind that makes up most of a real paper. It is not a timed mock paper: use a past paper from the official site for that.

7 · Glossary

Actual parameter
The value or variable passed to a sub-program when it is called.
Agile
An adaptive methodology: short sprints, constant client feedback, testing throughout.
Aggregate function
An SQL function that returns one value from many rows: COUNT, SUM, AVG, MIN, MAX.
Alias
A temporary column heading in a query result, given with AS.
Array of records
An array in which each element is a record.
Boundaries
The limits of a project, and the assumptions made about it.
Breakpoint
A marker on a line of code where execution pauses.
Cache
A small amount of fast memory on or near the processor, checked before main memory.
Cardinality
One-to-one, one-to-many or many-to-many: how many occurrences relate.
Compound key
A primary key made from two or more attributes, each a primary key in its own right.
Computed value
A value calculated in a query when it runs, not stored in the database.
Computer Misuse Act 1990
UK law covering unauthorised access, access with intent to commit a further offence, and unauthorised modification.
Data dictionary
A table describing every attribute: key, type, size and validation.
Data flow
The data passed IN to and OUT of each step of a design.
Descendant selector
A CSS selector such as nav ul that matches elements inside other elements.
Digital certificate
A document from a Certificate Authority that binds a public key to an identity.
Digital signature
Made with the sender's private key. It proves who sent a message and that it is unaltered.
DoS attack
Denial of service: stops genuine users reaching a service, through bandwidth consumption, resource starvation or DNS faults.
Entity occurrence
One instance of an entity (one row of a table).
Execution error
An error that crashes a program while it is running, such as dividing by zero.
Exponent
The part of a floating-point number that says where the binary point goes (stored in two's complement).
Extreme test data
Data on the boundaries of the valid range.
Fetch-execute cycle
Address bus → read line → data bus to the instruction register → decode and execute.
Fitness for purpose
Whether a solution meets every requirement in the specification.
Float / clear
CSS that pushes an element to the left or right / makes an element start below any floats.
Foreign key
A field that is the primary key of another table and links the two tables.
Formal parameter
A variable named in a sub-program's definition that receives the passed value.
Function
A sub-program that returns a single value.
GROUP BY
Groups rows that share a value so that an aggregate runs once per group.
Grouping selector
A CSS selector list such as header, nav, footer that applies one rule to several elements.
Iterative development
A predictive methodology: fixed phases in order, repeated when problems are found.
Local variable
A variable declared inside a sub-program, visible only there.
Logic error
The program runs but gives the wrong result.
Low-fidelity prototype
A quick, cheap mock-up of a website made from wireframes, used for early usability testing.
Maintainability
How easily the code can be changed: readability and modularity.
Mantissa
The significant digits of a floating-point number. More bits give more precision.
Modulus
The remainder after division (MOD, or % in Python).
Persona
A fictional, realistic user adopted by a tester during usability testing.
Private key
The secret half of a key pair. It decrypts messages, and creates signatures.
Public key
The shared half of a key pair. It encrypts messages to its owner, and verifies their signatures.
Procedure
A sub-program that carries out a task without returning a value.
Range (floating point)
How large and how small the numbers that can be stored are. More exponent bits give more range.
Record
A data structure grouping fields of different types.
Robustness
How well software copes with unexpected or exceptional input without crashing.
Scope (analysis)
The deliverables of a project and its time limits.
Scope (variable)
The part of a program where a variable can be used.
Sprint
A short agile development cycle that delivers a working increment.
Syntax error
Code that breaks the language's grammar, so it can't be translated.
Tracking cookie
A cookie that records browsing across sites to build a profile of the user.
Two's complement
A binary representation of integers in which the leftmost bit has a negative place value.
Unicode
A 16- or 32-bit character set covering all the world's writing systems.
Usability
How intuitive and easy a solution is for its users.
Watchpoint
Pauses execution when a chosen variable changes or a condition becomes true.
Wildcard
% (any number of characters) and _ (exactly one), used with LIKE.
Normalised
A floating-point number with its point moved to just before the first 1, so the mantissa starts 0.1.
Wireframe
A simple sketch of one screen's layout, showing the position of every element.
