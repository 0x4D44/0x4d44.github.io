The chart room · Web Design and Development (WDD)

Hoisting the squadron's website

WDD is the other option: Section 3 of the question paper (25 marks) or Task 3 of the assignment (15 marks), instead of Database. It has more to implement than Database (HTML, CSS and JavaScript), but less to design. In 2025, 34% of candidates chose it.

⚓ Ship's log: this site is built the same way

The bar of deck links at the top of every page is built like an SQA navigation bar: a <nav> holding a <ul> of links, styled with descendant selectors (nav.decks a) and a :hover rule. Every page also uses <header>, <nav>, <main>, <section> and <footer>. One difference: we line the links up with a newer CSS tool called flexbox. In the exam, use the float:left method shown in Chapter 5.

1 · Analysis: end-user and functional requirements WDD · identify

End-user requirements

What visitors to the site want to be able to do. "Parents should be able to see the dates of the summer camp." "Recruits should be able to register their interest."

Functional requirements

What the site must contain and do, described in terms of pages, media and code. "The Join page will have a form with a text input for the name (presence check, maximum 20 characters), a number input for age (range 12–17) and a submit button." "Clicking a ship's image will use JavaScript onclick to show its details."

⚠ From the 2025 course report

Web functional requirements "often lacked technical detail as they did not refer to the underlying code". Name the actual form element, validation or JavaScript event in your answer.

2 · Multi-level site structure WDD · home + two levels, ≤ 4 pages per level

At Higher, a site has a home page and two further levels, with no more than four pages per level. SQA draws the structure in a fixed style:

  • Shaded boxes are pages that appear in the horizontal navigation bar. That bar is at the top of every page, and the home page is always in it.
  • Horizontal lines join the navigation bar pages, because every one of them links to all the others (two-way links).
  • Vertical lines are one-way links, from a page down to its sub-page. (Our diagram adds small arrowheads to make the direction obvious; in the exam a plain vertical line means the same thing.)

3 · Wireframes, media and low-fidelity prototypes WDD · user-interface design

A wireframe plans the layout of one page. It needs to show:

  • the horizontal navigation bar
  • the relative horizontal and vertical positions of the text, images, video and audio
  • any form inputs (labelled with their type and validation)
  • the file formats of the media: text, graphics (JPG, PNG, GIF, SVG), video (MP4) and audio (MP3, WAV)

It must also take account of the end user and the device type. A smartphone wireframe usually stacks content in one column, with bigger tap targets.

Low-fidelity prototypes

A low-fidelity prototype is a quick, cheap mock-up made from the wireframes: paper sketches, or simple linked boxes with no real styling. It is good enough for users to "click" through and try the site before any code is written, so design problems are found while they are still cheap to fix.

Usability testing with personas, test cases and scenarios

Testers work through the low-fidelity prototype while observers note any difficulties.

Persona

A made-up but realistic user the tester pretends to be: "Moira, 52, a cadet's parent. Uses a phone and isn't confident online. Wants camp dates and the kit list."

Test case

A set of actions that checks one feature: "From the home page, open Join, fill in the form with valid data, then submit."

Scenario

A realistic task with a goal: "Your daughter wants to try gliding. Find out what she needs to bring."

4 · HTML: page layout elements WDD · nav, header, footer, section, main, form, id

HTML5 has elements whose names say what each part of a page is for:

ElementHolds
<header>The page banner: title, logo, often a link to the home page.
<nav>The navigation bar: a <ul> of links to the main pages.
<main>The main content of the page (one per page).
<section>A themed part of the content inside main: text, images, video, audio or a form.
<footer>General information at the bottom: contact details, copyright, legal links.
<form>A set of inputs for the user to fill in (Chapter 6).

A complete page skeleton looks like this. Each element sits inside the <body>, and the external stylesheet is linked in the <head>:

<!DOCTYPE html>
<html>
<head>
  <title>Sea Training</title>
  <link rel="stylesheet" href="squadron.css">
</head>
<body>
  <header><h1>1805 Squadron</h1></header>
  <nav>
    <ul>
      <li><a href="index.html">Home</a></li>
      <li><a href="sea.html">Sea Training</a></li>
    </ul>
  </nav>
  <main>
    <section id="gunnery"> … </section>
    <section> <form> … </form> </section>
  </main>
  <footer>Contact · © 1805 Squadron</footer>
</body>
</html>

Anatomy of a page

The id attribute gives one element a unique name on the page. CSS can style it with #name, and JavaScript can find it with document.getElementById("name"). A class can be shared by many elements; an id must be unique.

5 · CSS: appearance and positioning WDD · inline, internal, external; grouping and descendant selectors; display, float, clear, margin, padding, sizes

Three places to put CSS

TypeWhereExampleUse it for
InlineA style attribute on one element<p style="color:red">A one-off change to a single element. It overrides the other two.
InternalA <style> block in the page's <head><style> h1 {color:navy} </style>Rules needed by one page only
ExternalA separate .css file, linked from every page<link rel="stylesheet" href="style.css">The whole site. One file gives every page the same look, and a single edit changes them all. This is the most efficient option.

Efficient selectors

Grouping selector (comma)

One rule for several elements:

header, nav, main, footer {margin-top:5px}

This replaces four separate rules, so there is less code and it is easier to maintain.

Descendant selector (space)

Matches elements inside other elements:

nav ul {list-style-type:none}

This affects only the ul inside the nav, and not any other list on the page.

The box model: margin, padding and size

Every element is a box. Its width and height set the content area. Padding is space inside the border, which pushes the content in from the edge. Margin is transparent space outside the border, which pushes other elements away.

⛏ Building it in blocks

Picture a Minecraft build. The content is the item in the middle, the padding is a ring of wool around it inside the frame, the border is the frame of planks, and the margin is the ring of air blocks you leave so the next build doesn't touch it. Every ring is added on every side.

⚠ From the 2025 course report

"Few candidates were able to identify that the increased margin would exceed the given width", and fewer still explained that the images would then no longer match the wireframe: the last one drops to a new line. Remember that margin and padding are added to both sides. Some candidates added 10px to both sides of each section when the design wanted a 10px gap in total, which gave a 20px gap.

float and clear

float:left or float:right pushes an element to one side of its container, and following content wraps around it. That is how images sit beside text and how navigation bar items line up side by side. The float carries on affecting everything after it until something clears it: clear:both makes an element start below every floated element above it.

6 · Forms and validation WDD · input text/number/radio/submit, textarea, select; length, presence, range

A <form> collects input from the user. HTML can validate that input in the browser itself, with no JavaScript needed:

CheckHTMLMeaning
PresencerequiredThe field can't be left empty
Lengthmaxlength="20" (and minlength)Limits the number of characters
Rangetype="number" min="12" max="17"The number must be between the limits

Good practice

Give every input a name, and give radio buttons a shared name plus their own value. Radio buttons with the same name form a group, so only one can be chosen. At Higher, forms are not sent to a server, but the names are still expected.

7 · JavaScript: mouse events WDD · onmouseover, onmouseout, onclick

An event is something the user does. Higher uses three mouse events, written as attributes on an HTML element. The JavaScript inside the quotes runs when the event happens:

  • onmouseover: the pointer moves onto the element
  • onmouseout: the pointer moves off the element
  • onclick: the element is clicked (or tapped)

The code can change this element (the one with the event), or a different element found by its id, or it can call a function defined in a <script> block.

Three demonstrations from the chart table

Why use a function?

If several images all need to grow and shrink, write the actions once in a function such as displayLarger(this) and call it from every image. That is less code, and one change updates every image: more efficient and more maintainable.

8 · Testing and evaluation WDD · validation, navigation, media, compatibility; fitness for purpose, usability

TestHow
Input validationTry to make every form field accept wrong data: leave required fields blank, type too many characters, and enter numbers just outside the range.
Navigation bar worksClick every link in the bar on every page. Check that each one opens the right page and that every page can get back to the home page.
LinksCheck internal and external links. Look for orphan pages: pages that no other page links to.
Media content displays correctlyCheck that text, images, video and audio appear and play, in the positions shown on the wireframe.
Compatibility: device typeTest on a desktop, a tablet and a smartphone. Different screen sizes and resolutions can break layouts, shift alignment or overlap content.
Compatibility: browserTest in several browsers (Chrome, Firefox, Safari, Edge…). They can render fonts, CSS and form validation slightly differently.

Evaluation

Fitness for purpose

Does the site meet every end-user and functional requirement? Name any that it doesn't meet: "The site is not fit for purpose: the Events page has no form to book camp places, which was a functional requirement."

Usability

Is it easy to use? Is the navigation consistent, is the text readable, is the layout clear on every device, and are the form labels and error messages helpful?

Resolution, not "screen size"

In 2025 few candidates could explain a problem "related to resolution". Most wrote about screen width instead. A page built with fixed pixel sizes (body {width:800px}) takes up a different proportion of screens with different resolutions. On a low-resolution display it may not fit, forcing horizontal scrolling. On a high-resolution display it looks small. A small bitmap image stretched to fill a large area looks pixelated.
