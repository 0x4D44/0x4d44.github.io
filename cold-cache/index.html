Field report · October 2026

The Cold Cache

Where the tokens go when an AI coding agent stops to wait. Eleven days, four machines, 336,000 requests — and a five-minute gap that turned out to cost a quarter of the bill.

335,664model requests measured across four machines
8.1bninput-token equivalents spent on context
77%of that spent by sub-agents, not the main sessions
28%spent re-reading context after a pause of 5–11 minutes

The problemA conversation is re-sent every time

A language model has no memory between requests. Every time an agent runs a tool or answers a message, the whole conversation so far is sent again: the instructions, every file it has read, every command output. In a long coding session that is hundreds of thousands of tokens, re-sent hundreds of times a day.

What makes this affordable is the prompt cache. The first time the model processes a stretch of conversation, the provider can keep the model's internal state for it. The next request that begins with the same text skips the computation and loads the saved state, at a small fraction of the price.

The cache has a lifetime. Leave a conversation untouched for longer than that lifetime and the saved state is thrown away. The next request has to process everything from scratch, and pay to store it again. We call that a cold rewrite.

What happens to a tokenPrice, relative to plain input
Read from a warm cache0.05×
Plain input, not cached1×
Written to a 5-minute cache1.25×
Written to a 1-hour cache2×

The same token costs forty times more written cold at the one-hour rate than read warm. So the question that decides the bill is simple: how often does a conversation go cold, and why?

A common confusionWhy not skip the cache?

If a cold rewrite costs 2× and plain input costs 1×, it is tempting to think the cache is the expensive part. It is not, because of what happens on the request after.

RequestCachedNot cached
First, after a long pause2.001.00
Second0.051.00
Each one after that+0.05+1.00

By the third request the cache is ahead, and it stays ahead. On one machine over nine days, each cached token was read back about 92 times. Without the cache the same work would have cost roughly fourteen times more. The cheap read on every later request is paid for by the write premium on the first.

The premium only hurts in two cases: when the same context is written more than once, and when a write is never read back.

MethodWhat we measured

The agent keeps a local log of every request, including how many tokens were read from cache and how many were written. We built a small reporting tool that reads only the structural fields of those logs: token counts, timestamps and the kind of event that woke the session. It never keeps conversation text.

For every request it asks one question: was the previous context mostly re-written instead of read? If so, that is a cold rewrite, and the tool works out what ended the silence before it:

  • Work — the agent was waiting on something it had started, such as a build or a sub-agent, and that finished.
  • User — a person came back and typed.
  • Peer — a message arrived from another agent.
  • Cap — the session had hit a usage limit and resumed when it lifted.
  • Account switch and other — the remainder.

Rewrites caused by deliberately shrinking the conversation, or by changing model, are counted separately and left out. They are not waste.

Finding twoThe five-minute gap

Main sessions were writing to the one-hour cache. Sub-agents, it turned out, were writing to the five-minute cache: every one of them, on every machine. Nobody had chosen that. It was the default for anything outside the main conversation.

Five minutes is shorter than a test suite. A sub-agent starts a build, waits seven minutes for it, and comes back to find its whole context gone.

More than three-quarters of everything sub-agents wrote to the cache was a rewrite of something they had already written. And four in five of those rewrites had the same shape: a pause of between five and eleven minutes, ended by the sub-agent's own tool call returning.

Those 6,529 events rewrote 1,803 million tokens. At the five-minute rate that is about 2,250 million input-token equivalents: 28% of all context cost on the four machines, spent on pauses that a longer cache lifetime would have ridden out.

Finding threeMain sessions go cold too, for mixed reasons

Main sessions had the one-hour cache, so they went cold far less often: 601 times across the four machines. But each event was large, because a main session's context is large. Between a fifth and three-fifths of main-session cache writes were cold rewrites, depending on the machine.

The largest single cause was again work: a lead agent starts sub-agents or a long job, hears nothing for an hour or more, and wakes cold when it finishes. The second was simply the person stepping away. That one is not waste in the same sense; it is the price of lunch.

The gap pattern was sharp. Under fifty minutes, a main session almost never came back cold. Over an hour, it almost always did.

What we changedThree small things

  • Sub-agents now use the one-hour cache. One line of configuration, rolled out to every machine. It makes each write dearer (2× instead of 1.25×) in exchange for surviving any pause under an hour.
  • A waiting agent wakes every fifty minutes. While it has background work running, it checks on that work at least that often. The first purpose is to catch hung jobs. The side effect is that the cache never reaches its one-hour limit.
  • A lead agent checks in with its team every fifty minutes, for the same two reasons.

And the reporting tool now stores one summary record per day, so the before-and-after survives the logs being cleaned up.

PredictionWhat it should save

For the sub-agent change, the tool re-prices the same eleven days as if every sub-agent write had been at the one-hour rate, and every cold resume of 5–60 minutes had been a warm read instead.

That is about 2,057 million input-token equivalents, a third of sub-agent cost and a quarter of everything. The estimate already carries the downside: with no rewrites saved at all, the dearer write rate alone would have added 31–37%.

For the fifty-minute wake, the arithmetic is rougher. The 187 work-caused cold rewrites in main sessions cost about 106 million equivalents. Kept warm, they would have cost under 3 million as reads, plus roughly 6 million for the extra wake-ups themselves. Net saving: about 97 million, or 1.2% of the total.

The sub-agent change is worth about twenty times the wake rule. The wake rule earns its place by catching stuck work; the token saving is a bonus.

Roads not takenIdeas the numbers argued against

  • Poking a five-minute cache to keep it alive. The five-minute rate is cheaper per write, so in principle one could use it everywhere and send a tiny request every four and a half minutes. Keeping a context alive that way costs about 0.65× of it per idle hour, against 0.06× on the one-hour cache. It only wins if idle time is short, and it cannot help the case that matters: a sub-agent cannot be poked while it is inside a long tool call.
  • Compacting sooner. Shrinking conversations earlier would trim only about 7% of the cold rewrites on the machine we checked. Most cold events happened at ordinary context sizes.
  • Pasting the conversation into a fresh session. It costs the same. To the model, a resumed session and a pasted one are identical: text it has no saved state for.

CaveatsHow far to trust this

  • The savings are scenarios, not bounds. Agents may behave differently once pauses stop being punished.
  • The wake-rule estimate guesses the number of wake-ups from gap buckets, and leaves out the output tokens each wake produces.
  • Counts are a floor. Logs that had already been deleted cannot be counted.
  • One model only. Two machines used an older model for part of the window; those requests are excluded.
  • The tool's classifier was checked against an independent reference implementation on thousands of generated histories, fuzzed, and reviewed by a second model family. Two small diagnostic disagreements remain open; neither affects token totals.
The lesson that generalises: a default nobody chose was setting a quarter of the bill. It was invisible until something counted cold rewrites by cause.
